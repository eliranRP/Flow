Home's forecast row and the Forecast screen read the month forecast in one request (FLOW-1314, slice 4 of the FLOW-1275 plan). `app/src/month-forecast-query.ts` now calls `month_forecast(p_month, p_today)` with the Israel date, in place of the five reads the app made and built from (expected months, open invoices, the month's overrides, the projects' edits and the company currency), and turns the answer back into what `buildMonthForecast` returned: each item gets `currency` from the books' currency, `expected_on` null, `late_days` 0 and null for any field the answer leaves out; amounts become bigints; and the income, expense, moved and small lists are rebuilt from the items and sorted in the app with `localeCompare(.., "he")`, since the database's order is not ICU's for every Hebrew pair. A failed read shows the usual failed state with retry. The kept data follows: the forecast is kept under the new key `["month-forecast", preview, "answer", month]` with a rule that checks its items and totals, and the old key's rule is gone (the overrides, expected months, open invoices and currency keys stay: Home's late bills, Profit and the project page still read them). The builder's own chunk (`month-forecast-build.ts`) and the two tests of the shared reads that no longer exist go; the TypeScript builder stays in `packages/shared` for the dev samples, the stories and `?preview=1`. Visible change for viewers: the forecast now counts in the books' currency for viewers too (the old currency read answered writers only). The database is unchanged. The live smoke's read allowlist gains `month_forecast`. The sweep and `pnpm latency` figures for the new read are pending after the deploy.
