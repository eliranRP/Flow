Settings → התראות (FLOW-516, decision [0201](decisions/0201-push-device-row-and-test-push.md)). This device has its own row at the top, "המכשיר הזה מקבל התראות": on asks for permission and subscribes it from the tap, off unsubscribes this device only, in the browser and on the server, and a blocked permission says where to allow it (iOS Settings › Notifications › Flow on an iPhone). The three switches are now "מה לקבל · לכל המכשירים" and never subscribe a device. "מכשירים מחוברים" lists the caller's own devices (new read `list_my_push_devices`, no endpoint or key), and a line asks to connect this device when a switch is on and none is connected. "שליחת התראת בדיקה" sends one push to every connected device through push-send's new `test` kind, which takes only the user's own JWT and allows 5 an hour (`claim_push_test`). Every step of a turn-on now has its own timeout and reason, the browser's error name shows in a muted "שלב אחרון" line, an old key's subscription is replaced with one retry, and the screen never stays busy; the review card and setup step 7 use the same reasons. An expired session no longer drops the device's subscription; an explicit sign-out deletes its row (`push_unsubscribe` is granted to the app again, amending 0193). Failed sends are logged with the push service's host, status and a short answer. Runbook: [push.md](runbooks/push.md).
