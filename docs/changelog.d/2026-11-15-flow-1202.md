**FLOW-1202 (perf queue, Company profit and the forecast pages).** `company_next_month_inputs` without `p_rest` (next month's card, Company profit's month view) now carries `skips` for next month, the same keys `forecast_overrides_for` gives for its moved-out rows, so the app no longer sends that call beside it and the card's count is right from the first answer. A later month's page counts `skips[month]` from the full answer instead of reading the month's overrides; a page that can skip a row still reads them once, for the skip's undo. The `get_company_next_month_inputs` spec and `docs/mcp/TOOLS.md` name `skips`. No screen changes; no timings measured yet.
