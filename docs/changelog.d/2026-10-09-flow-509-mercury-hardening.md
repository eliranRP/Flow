Mercury sync hardening (FLOW-509). Skip records and recheck stamps are written in the same transaction as the synced lines, and a resumed run no longer duplicates skips. A later sync stops reading the treasury ledger 60 days before its window start (a cancel can carry its original's day) instead of reading the whole history, and the stored treasury read is bounded by date and count instead of failing past 20,000 rows. A treasury cancel voids the line on its own account first, and an unlabeled line only when the company has one treasury account; with two or more, a line stored before it carried `account_id` is no longer voided by a cancel (accepted gap). The drain posts Mercury to Vault `flow_mercury_sync_url` when it is set, falling back to the swapped sumit-sync URL. The Mercury path wildcards accept one plain id segment only. Both sync functions use the typed database client.
