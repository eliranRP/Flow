The project forecast in the database (FLOW-1309, slice 8 of the FLOW-1275 plan). New `public.project_forecast(p_project, p_month, p_today, p_currency)` (security invoker, execute for `authenticated` and `service_role`) gives a project's forecast for one month of the forecast (next month to 12 months ahead) in one read, in profit and cash terms, as the project page's card, its צפי page and its edit page read it today: the totals (income, expense, net, and the cash expense and net with the loans' payments the profit leaves out), the rows in the order the צפי page lists them, the rows the owner took out and the rows only a skip took out, the card's income note counts, whether an edit starts in the month, the month's overrides, the edit page's history and charges. It runs FLOW-1307's core on the one project (private.company_forecast_build, with one new optional input key, so a project with no row left is still listed; the company's answer is unchanged) and gathers that one project's charges, category months, edits, overrides and loans, with the loans' rest of schedule built per read. The company's overhead project gives the general costs. A project of another company, or a caller with no company, gets null, as `get_project` does; a bad project, month or currency is refused (22023). No app change: FLOW-1315 switches the project page, and it replaces FLOW-1233's planned inputs read. New shared vectors (`packages/shared/fixtures/vectors/project-forecast`, run by the app's own builders and by pgTAP) and a pgTAP file on the FLOW-1307 fixture company, equal to the app's builds. Measured on Flow QA-shaped data (14 projects, 22 loans, 1,867 lines): the largest project, next month, takes 69 ms and 14 KB, against 160 ms and 113 KB for the company's rows; the overhead project 123 ms.
