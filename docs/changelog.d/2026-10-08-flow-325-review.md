Three server follow-ups from the #135 review of the line split ([FLOW-325](backlog/TASKS.md#flow-325), [0138](decisions/0138-line-split-review-followups.md)). `get_project`'s `transactions[].parts_minor` is now signed against the line's own kind, the rule `save_line_split` uses, so a reversal part counts minus. A reversal part in a kept-out category no longer needs a project, unless the owner put the line in the P&L; putting a line with such a part in the P&L is refused with `a reversal part needs a project`. A part with no project counts as on the line's project when checking for the same category and project twice, so the server now refuses what the app screen already guarded. MCP `split_line` and `set_line_pnl` follow the same rules.
