Screens load faster from the cache. A read now stays fresh for 30 minutes and stays cached for 60 (`app/src/query-client.ts`), so going back to Home or a project draws from memory with no reads. Fresh data still arrives three ways: any write marks every cached read stale (the next screen reads again) and refetches its own keys; a finished bank or SUMIT sync refetches every ledger read; and coming back to the tab refetches the same list, at most once every 5 minutes. The list is `app/src/ledger-keys.ts` (projects cash, recurring schedule and changes, missing bills, expected months, categories, company currency, loans, the project's next-month reads and the rest); `ledger-keys.test.ts` fails when a read's key is neither in it nor one of the account reads (companies, team, settings, the setup run).

Home draws as soon as `cash_months` answers. It no longer waits for `get_dashboard`; the review count joins when that answers, and only a company with no recent cash line waits for it before the empty state. The setup resume reads its step facts (SUMIT, Mercury, Jev, review, loans) only while a setup run is open, so a finished or never-started setup adds no reads to Home. Loans takes the company from the app's memory and reads the loans, balances and project names at once. A project page starts from the Projects list's row and reads its lifetime profit and changed charges beside the project. The idle preload of the other screens waits until the first reads settle (8 seconds at most).
