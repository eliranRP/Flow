FLOW-133: MCP `undo_batch` undoes only the batch's own `split_line` or `set_line_pnl` write. Before, an `assign_expenses` `parts[]` row or a `set_lines_pnl` row undid the newest write of that kind on the line, so a later split or override was undone instead and the row read ok; now that row is `conflict` while the later write is live, and `not_found` once its own write is undone. `split_line` and `set_line_pnl` return `write_id` for this. Undo of a split now puts back each part's percent and rest marker. An `assign_expenses` `parts[]` row returns its stored parts in cents. Migration `20261009130000_batch_undo_write_id.sql`.
