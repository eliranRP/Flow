**FLOW-1171 (perf queue).** Home's late-bills list (`missing_bills`) and the forecast reads of recurring charges (`expected_months`: Home's forecast, Forecast, Company profit) no longer run two helpers once per charge. The suggestion for a renamed supplier or customer now makes each party's name words once and compares them for all due charges in one statement (`private.recurring_match_suggestions`, the same rule, picks and tie-breaks as `recurring_match_suggestion`), and the FLOW-1037 handover reads this month's line parts once for all eligible charges and reads the earlier lines only when a candidate exists (`private.recurring_handovers`, the rule of `recurring_handover`). Same answers: on Flow QA the ordered results of both functions have the same md5 as before. On Flow QA, `missing_bills` takes about 170 ms instead of about 450 ms (warm, in the database) and `expected_months(2)` about 115 ms instead of about 185 ms; what is left is mostly `recurring_parties` (about 100 ms). The per-charge helpers stay as the reference the new pgTAP file `recurring_setwise` compares against.
