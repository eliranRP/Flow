**FLOW-1171 (perf queue).** Home's late-bills list (`missing_bills`) and the forecast reads of recurring charges (`expected_months`: Home's forecast, Forecast, Company profit) no longer run two helpers once per charge. The suggestion for a renamed supplier or customer now makes each party's name words once and compares them for all due charges in one statement (`private.recurring_match_suggestions`, the same rule, picks and tie-breaks as the per-charge function before it), and the FLOW-1037 handover reads this month's line parts once for all eligible charges and reads the earlier lines only when a candidate exists (`private.recurring_handovers`, the same rule, and nothing is read when no charge is eligible). Same answers: on Flow QA the ordered results of both functions have the same md5 as before. On Flow QA, `missing_bills` takes about 170 ms instead of about 450 ms (warm, in the database) and `expected_months(2)` about 115 ms instead of about 185 ms; what is left is mostly `recurring_parties` (about 100 ms). The per-charge helpers (`recurring_match_suggestion`, `recurring_handover`) and `party_names_alike`, which only they called, are dropped: the name rule now lives once, in `recurring_match_suggestions`, on `party_name_words`. The new pgTAP file `recurring_setwise` keeps their last bodies as its oracle and compares the answers, including lines each filter must leave out.
