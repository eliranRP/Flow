Faster pushes (FLOW-813 follow-up, owner's pick 2026-10-09). The local gate's default run is scoped to what the branch changes against main (`git diff origin/main...HEAD`), so a merge of main re-runs nothing for main's own changes. App unit and Storybook vitest tests run for the files the branch changes. At most 6 e2e specs run (`FLOW_E2E_MAX`), the branch's own specs first. The Storybook build and its layout specs run only when a story spec or the Storybook setup changes. A migration or pgTAP change now passes on the default gate: a fresh local database, the flow-mcp smoke, the db types check, and the pgTAP files that name what changed (`scripts/pgtap-specs.mjs`). Main's CI still runs everything before each deploy.
