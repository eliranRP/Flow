Faster pushes (FLOW-813 follow-up, owner's pick 2026-10-09). A push whose patch against main already passed (a merge of main that changes nothing of the branch) passes in seconds, and a docs-only push runs lint and the file-size check only. Each run logs its parts and time to `gate-times.log`. The local gate's default run is scoped to what the branch changes against main (`git diff origin/main...HEAD`), so a merge of main re-runs nothing for main's own changes. App unit and Storybook vitest tests run for the files the branch changes. At most 6 e2e specs run (`FLOW_E2E_MAX`), the branch's own specs first. The Storybook build and its layout specs run only when a story spec or the Storybook setup changes. A migration or pgTAP change now passes on the default gate: a fresh local database, the flow-mcp smoke, the db types check, and the pgTAP files that name what changed (`scripts/pgtap-specs.mjs`). Main's CI still runs everything before each deploy.
