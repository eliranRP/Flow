CI runner stalls (FLOW-1319): jobs on 2026-11-23 and 2026-11-24 failed on "Wait for local Supabase" (runs 45337772314, 45355355807, 45363569659) or on apt in the deploy's live smoke (run 45331469028), and each needed a re-run. The Supabase waits were one bug: the step shell runs with `-e`, so when `supabase start` failed (reproduced: `failed to bind host port 0.0.0.0:54322/tcp: address already in use`, because the runner can hand 54322 out as the source port of an outgoing connection) the background wrapper died before it wrote the exit file, and the wait step waited its 8 minutes for a failure that came in the first minute. The wrapper now runs `set +e`, the start script reserves ports 54320 to 54329 with `ip_local_reserved_ports`, limits every call (the diagnostics too) with a hard stop, starts at 120 s per attempt (healthy starts take 61 to 96 s) with up to three attempts inside a 330 s budget, and logs the sockets on the Supabase ports on failure; a new `ci-supabase-wait.sh` prints the start log, `docker ps -a` and the processes if a start ever stalls. The apt fallback to archive.ubuntu.com did nothing on the Ubuntu 26.04 runners (their mirror is in `/etc/apt/apt-mirrors.txt`, and the host pattern missed digits and hyphens); it now rewrites that list, `install` and `psql` write the apt timeout and retry settings, and the deploy job restores the Playwright apt cache before the live smoke. No test is retried, skipped or changed; the same Playwright shards run.
