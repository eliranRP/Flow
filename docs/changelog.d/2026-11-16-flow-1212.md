FLOW-1212 (perf). On a project page opened from the Projects list, the one-project read behind the ⋯ menu's figures (the waiting-lines count and the delete state, `projects_cash_month` for that project) no longer goes out while the page is still mounting. It starts after the page's first paint. Touching or focusing the ⋯ button, or pressing a key on it, starts the read at once, so a menu opened after that shows its figures without a wait. If the menu opens before the read has landed (a very fast open right after the page loads), the menu shows its existing placeholders until the read lands, as it did before this change. A deep link to a project page, which has no list row to start from, still reads at mount. The other project pages that read the same project row (detail, profit, utilities, utility bills) also wait for the first paint when they start from the list row; the figures they show are the list's and do not change. The row-touch prefetch is unchanged. Nothing on screen looks different. The reads per visit do not change: the same read is sent once, and it is sent a moment later than before, not skipped when the menu stays closed.
