The project page stays fast when the database has no fresh row counts for a company's tables, as with a small or freshly synced company. `get_project`, `private.project_category_entries_by_currency` and `private.project_investment` read the project's lines first and look up each line's allocation and transaction by index, so a wrong row guess can no longer loop every allocation over every line. `private.overhead_share_for` reads only the company's income and overhead lines. A pgTAP case runs `get_project` on 2,100 lines with no statistics and fails above 3 s (it took about four minutes before). Every result stays the same.
