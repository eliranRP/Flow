Loan outlooks in the database (FLOW-1310, slice 10 of the FLOW-1275 plan). New `public.loan_outlooks(p_today)` (security invoker, execute for `authenticated` and `service_role`) answers, for each open loan with a built schedule, the next payment (date, interest, escrow, principal, amount), the next 12 payments' total, the total to the end, the end date and FLOW-1258's late date, in one read: `[{ loan_id, next, ahead_minor, to_end_minor, end_date, late_on }]`, absent = null, a loan with neither a next payment nor a late date left out. `private.loan_outlook_build(jsonb)` is the same arithmetic as `loanOutlook`, `remainingFromBalance` and `latePayment` for one loan, an immutable function that reads no table and gives the figures the app's builders give for 32 shared vectors (`packages/shared/fixtures/vectors/loan-outlook`, run by `app/src/screens/loan-outlook-vectors.test.ts` and the generated `vectors_loan_outlook.test.sql`). The stored schedule (FLOW-1306) gives the due dates; the rest of each schedule is built from the balance on each read, about 34 ms and 6 KB for 22 loans locally. `p_today` null is today in Israel. No existing read changes and the app does not call it yet (FLOW-1316). pgTAP `flow_1310_loan_outlooks.test.sql`; `scripts/vectors-sql.mjs` now writes a file for the loan-outlook core; the vectors README now says all three cores exist and that each compares exactly, one `is` per vector.
