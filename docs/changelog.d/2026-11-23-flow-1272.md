FLOW-1272: Review's first card needs two waves of reads after the tap, not three. The Jev connector's read starts with the list (the company is the one Home's cached dashboard names, or the company's own read when there is none), so the suggestions go out the moment the list's answer lands, without waiting for the read schemas; the `jev-review` chunk and the card's categories are requested when the list's read starts, not after its answer. Home's Jev bookings count and Review's queue are one `list_jev_bookings` read under one key, so Home's read serves Review; that read is no longer retried after a failure on Home either (one query has one retry setting), and Home counts a failed read as zero as before. On a local production build with the stub backend (CPU 4×, 9/1.5 Mbps, 412×915), after a launch that left Jev on, a Review visit draws its first card at a median of 612 ms against 771 ms (12 visits each; a second pair of runs gave about 590 against 670 ms), and sends 12 reads in 2 waves, not 3. With no remembered Jev flag the gain is within noise. The bundle total is unchanged (2 bytes less), the Home entry 50 bytes more; nothing the screens show changes.
