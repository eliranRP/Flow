Security (FLOW-945): flow-mcp now caps unauthenticated `/mcp` floods with a cheap in-memory gate before any database call, closing a DB-load amplification path a security review found. An unauthenticated request used to run `note_auth_failure` (a DB upsert), and for a `flow_mcp_`-prefixed token one `lookup_mcp_credential` per pepper, before any throttle applied; and because that throttle keyed on the client-settable `cf-connecting-ip`, a request with no such header skipped it entirely. The handler now keeps an isolate-local fixed-window counter: a trusted client IP gets 60 failed pre-auth attempts per 10 seconds and all requests with no IP share one global bucket of 240 per 10 seconds, and going over returns the existing `rate_limited` 429 with `retry-after` without touching `lookup_mcp_credential` or `note_auth_failure`. Only failed attempts are counted, so an authenticated caller is never throttled, and the durable DB-backed `note_auth_failure` counter is unchanged as the authoritative cross-isolate layer. Tokens stay 256-bit random, so this was never an auth bypass. No migration.
