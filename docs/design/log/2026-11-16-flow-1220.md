# FLOW-1220: the project ⋯ menu keeps a quiet line where the delete row would be

- PR: #1212
- Kind: fix
- Changed:
  - `app/src/screens/project-menu.tsx`: when the menu's read lands and the project cannot be deleted, the delete slot is a static row, "אי אפשר למחוק: יש בו תנועות", with the bin icon in the muted tone and no chevron. It is not a button and does nothing. Before, the slot was empty, so the rows above moved up by a row when the read landed. The skeleton, the quiet line and the delete row share the row's height (`--row-height`), so the rows do not move in any of the three states. The quiet line takes no hover tint. The failed read's row ("לא הצלחנו לבדוק אם אפשר למחוק", from FLOW-1204) wraps to two lines at 320, so in that rare case the rows above still move about 8px.
  - Tests and stories: `project-menu-figures.test.tsx` (the line shows the text, is not a button and has no chevron), and the story "Project, ⋯ menu, can't delete" in `project-detail-screen.stories.tsx` (a project with lines, shot at 320 and 393).
- Rule:
  - A slot that a read may fill with an action, a warning or nothing keeps its height: when the read says no action applies, the slot shows a quiet, non-tappable line in the same place, not an empty space.
- Source: UX rules review 2026-11-16 (the owner asked for the fixes). Owner's pick 2026-11-16: "Keep a quiet line" (FLOW-1220, option a).
