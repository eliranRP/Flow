# FLOW-512: Settings as a menu, its inner pages, and the SUMIT, Mercury and MCP pages

- PR: #628
- Kind: screen
- Changed: `app/src/screens/settings-screen.tsx` (the menu), `business-screen.tsx` (new), `connection-page.tsx` and `connection-pages.tsx` (new; the SUMIT and Mercury pages), `assistant-settings.tsx` (the חיבור ל־AI page), `connections-screen.tsx`, `connections-status.ts`, `team-screen.tsx`, `team-sheets.tsx`, `person-row.tsx`, `notifications-screen.tsx`, `rename-company.tsx`, `company-choices.ts`, `ui/list-row.tsx` (the `value` slot), `ui/toggle.tsx` (a locked switch names the viewer note), `design/system/implementation-tokens.css` (`--color-switch-off`, `--radius-card-tight`), `app/src/ui/css/10-settings-onboarding.css`, `app/src/routes/settings.tsx`; removed: the connector status sheet and the row tests that tested it.
- Rule: Settings is a menu of rows with a short value at the end. Each area opens its own page; a page has one back link to its parent. Connectors (SUMIT, Mercury, the MCP code) are the owner's; a viewer or an editor reads them and sees why they cannot change them. The switch-off track uses `--color-switch-off`; cards with the tighter radius use `--radius-card-tight`.
- Source: the FLOW-512 task file and the Settings boards in the Design canvas ("Ready for dev"); lead decisions recorded on the PR.

## Differences from the board

1. The SUMIT and Mercury success toasts use the hook copy, not the board's "N מסמכים חדשים נכנסו".
2. The connection page's error state (a failed status read) is not rendered as its own sample yet; the page shows the shared failure screen.
3. Facts the status read does not return ("נכנסו עד היום", card and bank details) are left out.
4. The MCP connected page does not show the assistant's name or the request count; `mcp_credential_status` does not return them. See FLOW-515.
5. The team row uses an initials avatar, not the generic user icon.
6. The connections list uses the note icon for the AI row (no chat icon in the set).
7. Sign-out is a danger text button, as the board shows it.
8. The problem copy has no date: the status view has no time of the last error.
9. Onboarding still uses the old connect sheets until FLOW-514.
