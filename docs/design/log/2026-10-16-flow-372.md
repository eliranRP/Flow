## Differences between the board and the task file

1. **Raised.** The task file says "surface and raised #FFFFFF; inner box / input #F1EEF6". The board pairs the dark value of `--color-raised` (`#251F33`) with "Inner box, input" (`#F1EEF6`), and DESIGN-RULES 2.2 names `raised` as "Inner box and input". The board wins, so `raised` is `#F1EEF6` and `surface` is `#FFFFFF`. The owner should confirm. If raised must stay white, the inner box needs its own token. Consequence: muted text on the inner box is 4.31:1, below AA (see Contrast).
2. **Strong line.** The task file gives `#DAD3E6` with no token. The board uses it for the secondary outline, the toggle off track and the dashed add row. It is now `--color-line-strong`. Its dark value `#3A3350` comes from the board. No screen uses it yet.
3. **Selected outline.** The task file gives `#D9CBF6`. The board's dark selected outline is `#382A5E`, which is `--color-tint-strong`, so the light value is set on `tint-strong`. Side effect: the secondary button outline (which uses `tint-strong` today) becomes `#D9CBF6`, where the board uses `#DAD3E6`. Other `tint-strong` fills (`demo-player.css`, `38-related-charges.css`, `14-review-change.css`) get the stronger lilac too. Owner to confirm, or move the secondary outline to `line-strong` in the Button PR.
4. **Track.** The task file says the track comes from the board. The board's light job bar is `#E7E2F0`, so it is set, replacing the `#F3ECFE` placeholder.
5. **Toast text.** The task file is silent. The board's toast text is `#F6F4FA`, so it is set (it was `#FFFFFF`).
6. **Bad and error.** The board names only "Signal". In dark, `bad`, `error` and `signal` share one value, so the light values follow the signal (`#D23B2F`, was `#C3302B`).
7. **Shadows.** The task file gives the shadow colour. The only shadow token is `--shadow-pill`. The board's sheet and side shadows (`8px 0 24px`) are not tokens in the app, so they are not set here.
8. **Sheet scrim.** Board `rgba(29,23,40,.38)`, app `rgba(29,23,40,.45)` today. Left alone, as the task file says (PR #609).

## Contrast (WCAG AA, 4.5:1)

Required pairs on the light background and surface all pass (`light-tokens.test.ts`): text 15.96 / 17.42, secondary 6.62 / 7.22, muted 4.53 / 4.95, accent 6.41 / 7.00 (on the background / on the surface).

Outside the required set, found while checking the board's values:

- Muted text on the inner box (`#F1EEF6`) is 4.31:1, and on the tint (`#EEE6FD`) it is 4.09:1. Both fail AA. Hints and placeholders in inputs are muted text, so this matters.
- Signal text (`#D23B2F`) on the background is 4.37:1, which fails for text. On the surface it is 4.77:1.
- Money in (`#1A8048`) passes on both (4.55:1 and 4.97:1).

## Theme store and the pre-paint script

- The choice is one of `system`, `light`, `dark`, saved under `flow.theme`. A missing, unknown or blocked value reads as `system`.
- `system` removes `data-theme` from `<html>`, so `prefers-color-scheme` applies. `light` and `dark` set it.
- index.html applies a saved light or dark choice before first paint, with a tiny inline script. It sits before the app module. Storage errors are caught.
- `ThemeColor` already re-reads the tokens when `data-theme` changes (its MutationObserver), so it follows the chosen theme. A test checks it.
- The inline script runs in CSP terms only if the policy allows it. The repo's `app/public/_headers` sets no CSP today. The tech plan (`docs/tech/tech-plan.md`) describes a strict `script-src 'self'`, which blocks inline scripts. When that policy ships, add the script's hash, or move the script into a same-origin file.
