# FLOW-966: Add v2, the UX/UI rules review

- PR: #827
- Kind: screen, component, copy
- Changed: `app/src/screens/add-entry-view.tsx` (the errors, the save label, the date picks, the chip radiogroups, `dir="auto"` on the payee), `app/src/screens/add-entry-sheet.tsx` (the toasts' place and times, offline, the camera for צירוף צילום), `app/src/add-entry.ts` (`entryProblems`, `datePresets`; `isEntryReady` is gone), `app/src/ui/chip.tsx` (a `radio` mode: `role="radio"` and `aria-checked`), the CSS in `44-add-entry.css` and one rule in `03-controls.css` (a checked radio chip looks like a pressed one), decision 0217.
- Rule:
  - Save is never disabled. A tap with something missing writes nothing and marks each field: `aria-invalid`, and its reason under it, linked by `aria-describedby`, with an alert icon (13px, `--color-bad`): "חסר סכום", "למי שילמתם? למשל שם הספק" / "ממי הכסף? למשל שם הדייר", "התאריך צריך להיות dd/mm/yyyy", the cheque's number, "בחרו פרויקט, או "בלי פרויקט"", "בחרו קטגוריה". The first missing field takes the focus (an input, or the first chip of its group). A wrongly typed date says so at once, the rest wait for the first tap.
  - The button names what it saves: שמירת ההוצאה / שמירת ההכנסה, and שמירה וצירוף לתנועה for a matched receipt. It is busy while the write runs.
  - Field, amount and dashed edges (+ פרויקט חדש, + קטגוריה חדשה, צירוף צילום) are `--color-control-edge` (#8F879F dark, #7A6E92 light, 3:1 and more on the field), an unchosen chip's edge too; a field with an error takes `--color-bad`. Placeholders are the muted text (#978EAB dark, 5.1:1).
  - The form's chips, the dashed add chips and the segmented סוג and אמצעי are 44px (`--touch-min`).
  - The date row has two quick picks, היום and אתמול (the phone's day); the one that matches is pressed.
  - The project chips and the category chips are each one radiogroup named by its label; בלי פרויקט is one of the project radios (owner, 2026-10-26: all four fields required, בלי פרויקט counts).
  - The payee field is `dir="auto"`, so a Latin name reads left to right.
  - צירוף צילום (לא חובה) opens the camera.
  - Every toast hangs under the header: an undo 5s, a note 4s (decision 0217).
  - Type on the scale: the menu tile's sub line is 13px, not 12.
  - Offline, a save writes nothing and says "אין חיבור. הטופס נשאר פתוח: נסו שוב כשהחיבור יחזור.", so nothing typed is lost and nothing claims to be saved.
- Source: owner approval on 2026-10-26; the Add row on the design canvas, page "Ready for dev", and its findings note. Owner calls the same day: an offline save is kept on the device and sent when back online; amount, payee, project and category are all required, בלי פרויקט counting.
- Departures from the approved board:
  - The offline save on the device ("שמירה במכשיר", sent when back online) is not built yet. The app has no queue for writes: `create_manual_line` takes no idempotency key, so a replay after a dropped answer could add the line twice. Until that is decided, offline says so and keeps the form open.
  - The camera states ("אין גישה למצלמה" with בחירת קובץ) and the could-not-read state (צילום שוב / מילוי ידני) are not built: the app opens the phone's own camera through a file input, which cannot tell a refused permission from a cancel, and it does not read receipts (FLOW-306 hashes the file only). The board's in-app camera and reading are a separate feature.
