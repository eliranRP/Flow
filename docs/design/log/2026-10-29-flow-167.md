# FLOW-167 + FLOW-168: a description a search found, and a long project in a row's hint

- PR: #865
- Kind: shared component, screen
- Changed: `app/src/ui/list-row.tsx` (the one-line hint's parts; a `wrapTitle` prop), `app/src/ui/css/02-fields-sheets.css` (`.ui-row-title-wrap`, the row hint's `.ui-hint-part`, `.ui-hint-sep`, `.ui-hint-text`), `app/src/screens/report-lines-screen.tsx`.
- Rule:
  - A report's category lines, searched: a line found only by its description shows the description as its title and the date and supplier in the hint. The title wraps, so the matched word stays in view at 320; a Latin description reads left to right, a Hebrew one right to left. Before, the description was one hint part, and a Latin one was cut at its start ("…lacement, unit 2 · 18/10").
  - A list row's one-line hint ("18/10 · <project>"): whole parts in order, then the first part that does not fit is cut with "…" while a few letters of it still fit. Before, that part wrapped to the hidden second line, so a long project name vanished and only the date showed. A part with less room than that still drops whole; a date or an amount never shortens; a first part too long on its own is cut, as before. Each part's text takes its own direction, so a Latin project name is cut at its end.
  - For the design lead: DESIGN-RULES still says a transaction row's hint part "drops with its ·" (FLOW-124) and "a hint part shows whole or not at all" (FLOW-339 Search); both need this rule's exception when they are folded in. The wrapping description title has no line cap yet (DESIGN-RULES caps a name at 2 lines, FLOW-339 loans).
