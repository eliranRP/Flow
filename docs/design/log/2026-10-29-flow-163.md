# FLOW-163: Reports: open them from a project page and from search

- PR: #864
- Kind: two new ways into the reports (FLOW-161), beside the Home card: a band button on the project page and a report group in the search results
- Changed: `app/src/screens/project-cash-screens.tsx` (`ProjectReportsLink`, in the band's end beside ⋯), `app/src/screens/project-detail-screen.tsx` (the loading band draws it too), `app/src/search-reports.ts` (new: which reports the typed text names), `app/src/screens/search-parts.tsx` (`SearchReportShortcuts`), `app/src/screens/search.tsx`, `app/src/reports.ts` (`reportsTo`, which the Home card's two links now use too). CSS: `css/32-project-page.css` `.ui-project-band-end`, `.ui-band-reports`; `css/19-search-screen.css` `.ui-search-reports-list`, and the searching view's side padding for `.ui-search-reports`.
- Rule:
  - The project page's band row ends with "דוחות" (the document icon and the word), a 44px pill of white on the band's 10% white track, then ⋯. It opens the reports already on that project: this year's P&L, with the balance sheet one tab away. The loading band draws it too, so nothing moves when the page lands.
  - In the search, when the text names a report, a "דוחות" section comes first in the results, above the project shortcut and the lines, and stays when no line matches. Each row is the project shortcut's row (36px tint tile, title, muted hint, chevron) with the document icon in the tile.
  - "מאזן" gives "מאזן" with "כל הפרויקטים · היום"; "רווח והפסד" gives "רווח והפסד" with "כל הפרויקטים · השנה"; "דוחות" (or "דוח", "reports") gives both, the P&L first as on the Home card. Close forms count: a "דוח" before the name, gershayim and typographic quotes ("רו״ה", "רוו״ה", "דו”ח"), English ("P&L", "balance sheet", "profit and loss"), and the start of a Hebrew name from three letters ("מאז", "רוו"). English names match only whole, since "pro", "inc" or "rep" begin too many words.
  - "דוח" with other words that name no project ("דוח חניה", "statement fee") is a line's own text: no report row.
  - With a project's name beside the report's ("מאזן Cedar", "דוח רווח והפסד של שיפוץ"), the row reads "<report> · <project>" with only the date word as its hint, and opens the report on that project.
- Source: the approved reports design, boards ReportEntryProject and ReportEntrySearch (page "In design · for approval", row "How the user gets to דוחות"), 2026-10-28; the owner approved both ways in on 2026-10-29.
- Decided: the owner approved the P&L as the band button's target on 2026-10-30 ([decision 3](2026-10-30-owner-decisions.md#3-the-project-pages-דוחות-opens-the-pl)).
- Departures from the approved board:
  - The board's project-page button links to the balance sheet. Here it opens the P&L on the project, the reports' default and what a project's owner checks first; the balance sheet is one tab away and keeps the project.
  - The board draws the button on a plain header. The project page has the violet band, so the pill takes the band's on-band colours (white on the 10% white track, as the band's segmented control), not the board's tint fill.
  - The board's search shows a "מאזן · <project>" row under "מאזן" without the project being typed. Here a project row shows only when the text names the project: a guess at which project the user means would often be wrong.
  - The board heads the lines with "תנועות" and a one-line "אין תנועות עם …". The search keeps its own count line and empty state under the reports, so a report search looks like any other search below its group.
