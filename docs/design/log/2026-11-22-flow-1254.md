# FLOW-1254, FLOW-1255, FLOW-1249: Home's late row draws once and hides the right item

- PR: #1250
- Kind: UI, behavior (no new look)
- Changed: `forecast-skip.ts` (`useLateBillsQuery` gives no list until the month's overrides are in, and waits for them when the screen turns them on later); `HomeScreen.tsx` (says its overrides are due once the books show); `attention-rows.tsx` (a named late row's hide key carries its item); `project-attention.tsx` (the late rows keep that key).
- Rule: a loading state does not show content that is about to change. The late row draws once, at its final count and name, a moment later when the overrides are slow. If the overrides read fails, the whole list draws: an error never hides an alert. A read that will not run on a screen is never waited on, and neither is one that is paused offline (the whole cached list draws, as on main). A hung overrides read holds the row until it settles; it has `retry: 1`.
- Rule: a hide applies to the item the person hid. A named late row's key is `missing:1:<party>:<project|none>` (income: `missing-income:1:...`); two or more keep `missing:<count>`. The old `missing:1` no longer matches a named row, so a row hidden before this shows once more (an alert showing again is the safe side, feedback-and-states section 4). A single late row with no party has no item to key by, so it keeps `missing:1`: party-less single late rows still share one hide key.
- Source: UX rules review 2026-11-22.
- Unchanged: the late count rows, the charge links, the skip filter itself, Home's rule of no forecast-side read before first paint.
- Tests: the 2 to 1 named-row test builds the rows through `attentionRows` rather than rendering Home; the offline and cold-currency holds are tested too. Also: the hook's pending, landed, failed and never-enabled cases; Home's 2 to 1 named row and its link; hide keys. No new state is visible, so no story changes.
