# FLOW-939: Several AI (MCP) keys

- PR: #760
- Kind: screen
- Changed: `app/src/screens/assistant-settings.tsx` (the page now has three views: the key list, `/key/<id>` and `/new`; with no key it is the setup), `app/src/screens/assistant-key-views.tsx` (new: `KeyList`, `KeyPage`, `AllKeysLink`), `app/src/screens/assistant-setup.tsx` (new: today's setup moved out of the page, with the "שם למפתח" field on top), `app/src/screens/assistant-keys.ts` (new: the key type, the status read, mint, revoke, restore, the default name and the toast words), `app/src/ui/icons.tsx` (`KeyIcon`, the board's key), `app/src/ui/css/10-settings-connect.css` (`.ui-ai-all-keys`).
- Rule: Once there is a key, חיבור ל־AI opens on the list: the head "מפתחות פעילים · N" (active keys), a card with a row per key (the key icon, the name, the last use under it, the access at the end in accent for קריאה וכתיבה and grey for קריאה בלבד, a chevron), the outline "+ מפתח חדש", and the grey line on a key per assistant and device. A key's page starts with "‹ כל המפתחות" (15px accent, a 16px back chevron, 44 tall), then the card of the connected page with the key's name and its access, the facts עוזר, שימוש אחרון, נוצר and בתוקף עד, and the logged-with-the-key's-name line; "ביטול המפתח" is the signal-colour text button under it. A new key runs today's setup with "‹ כל המפתחות" and the "שם למפתח" field (placeholder "למשל: Claude במחשב העבודה", at most 60) first; once a code is shown the field holds the name the key got. סיום, or the assistant's first call, returns to the list with "המפתח נוסף · N מפתחות פעילים". A revoke returns to the list with "המפתח בוטל · <name>" and ביטול.
- Source: board canvas note spec-mcp ("SEVERAL AI (MCP) KEYS", approved), Settings and SettingsLight boards (`mc`, `keys`, presets `mcpkeys`, `mcpkey`, `mcpnewkey`), the SettingsMcpKeys, SettingsMcpKey and SettingsMcpNewKey frames and the changed SettingsMcpConnected frame, 2026-10-20; decision [0202](../../decisions/0202-several-mcp-keys.md).
- Departures from the board:
  - The name field also shows in the first key's setup (the board draws it in every setup; the note says the no-key page is "today's setup").
  - A last use reads in the app's existing words ("שימוש אחרון ב-21:40", "שימוש אחרון אתמול ב-08:12", then the date), not the board's "שימוש אחרון היום 21:40"; the key page's שימוש אחרון has no request count ("· 12 בקשות"), which the app does not keep per key. No use yet is "עוד לא בשימוש", as on the board.
  - With one key the toast says "המפתח נוסף · מפתח פעיל אחד" (Hebrew for one), not "1 מפתחות פעילים".
  - The note does not cover expired keys. An expired key stays in the list after the active ones with "פג תוקף" in the signal colour where the access is, and its page shows בתוקף עד in the signal colour; while no key is active the list opens with today's tinted box ("הקוד פג אחרי 90 יום. צרו מפתח חדש כדי להמשיך."). The head counts active keys only.
  - A key made before this change has no name or assistant: it shows as "מפתח AI" and its page has no עוזר row.
  - The 21st active key is refused with "יש כבר 20 מפתחות פעילים. בטלו מפתח שלא בשימוש ונסו שוב." (the board has no cap).
  - The revoke's undo works for 10 minutes on the server; after that the key is gone for good.
  - Changing the access after a code is shown revokes that code (it was never used), as the single-key mint did; changing the assistant keeps the code, and the key keeps the assistant chosen when it was made.
  - The list is in the order the keys were made, oldest first (the board's sample lists its newer key first but adds a new key at the end).
  - Step 4 says the key "יופיע ברשימת המפתחות" instead of "יופיע כאן כמחובר", since the page now returns to the list.
  - No rename: neither the note nor the board has one.
