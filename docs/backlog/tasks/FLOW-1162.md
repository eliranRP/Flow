# FLOW-1162 · Mercury sync: a page-capped run resets the missing-since clocks; the cursor's phases as one table
- **Type:** BUG · **Status:** ready · **Depends on:** [FLOW-1160](FLOW-1160.md)
- **Source:** the state machine read of 2026-11-10 ([map](../../tech/state-machines.md), FLOW-1160). Read in the code, not run: check each still happens on `main` first.
- **Files:** `supabase/functions/_shared/connectors/engine.ts`, `supabase/functions/_shared/connectors/mercury/client.ts`, `supabase/functions/mercury-sync/index.ts`, their tests and fixtures.

- [ ] A run that stops at the page cap writes an empty `settings.pending_missing`, because the engine fills it only on a complete fetch while the function writes it every time. Every pending line's 10-day wait before it is voided starts again. Keep the stored clocks on an incomplete run.
- [ ] A passing error on a recheck starts a pending line's missing clock though Mercury did not answer 404.
- [ ] A treasury resume whose account is no longer listed restarts at the first account and sends it the old page token.
- [ ] A repeated page token ends the run as rejected with the cursor unchanged, so every later run repeats it.
- [ ] After a resumed run completes, lines listed by the earlier partial run count as unseen and use up the 50 rechecks.
- [ ] The cursor's phases (`window`, `pending`, `treasury`, done) and which run after a resume become one table (decision 0266); the commit's three steps (lines and cursor, labels and clocks, the stamp) are named states.

**Acceptance:** a connector test per box, on invented fixtures; the map's rows updated.
