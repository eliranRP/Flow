# FLOW-1162 · Mercury sync: a page-capped run resets the missing-since clocks; the cursor's phases as one table
- **Type:** BUG · **Status:** ready · **Depends on:** [FLOW-1160](FLOW-1160.md)
- **Source:** the state machine read of 2026-11-10 ([map](../../tech/state-machines.md), FLOW-1160). Read in the code, not run: check each still happens on `main` first.
- **Files:** `supabase/functions/_shared/connectors/engine.ts`, `supabase/functions/_shared/connectors/mercury/client.ts`, `supabase/functions/mercury-sync/index.ts`, their tests and fixtures.

- [x] A run that stops at the page cap writes an empty `settings.pending_missing`, because the engine fills it only on a complete fetch while the function writes it every time. Every pending line's 10-day wait before it is voided starts again. Keep the stored clocks on an incomplete run.
- [x] A passing error on a recheck starts a pending line's missing clock though Mercury did not answer 404.
- [x] A treasury resume whose account is no longer listed restarts at the first account and sends it the old page token.
- [ ] A repeated page token ends the run as rejected with the cursor unchanged, so every later run repeats it.
- [x] After a resumed run completes, lines listed by the earlier partial run count as unseen and use up the 50 rechecks.
- [x] The cursor's phases (`window`, `pending`, `treasury`, done) and which run after a resume become one table (decision 0266); the commit's three steps (lines and cursor, labels and clocks, the stamp) are named states.

**Acceptance:** a connector test per box, on invented fixtures; the map's rows updated.

**In #1125:** fixed the page-capped run's clocks, the clock a passing recheck error started, and the treasury resume to an account that is gone; the fetch phases and the commit steps are tables (`_shared/connectors/mercury/machines.ts`). **Decisions needed:** a repeated page token (end the list there, save what was fetched and move on, or keep failing and stop after a few attempts); a resumed run using up its 50 rechecks on lines the earlier partial run listed (carry the seen ids in the cursor or in settings, or skip rechecks on a resumed run). The commit is still three steps, not one transaction.

**Decided by the owner, 2026-11-10:** a repeated page token keeps failing the run, but after a few attempts the sync stops retrying and the connection shows as needing attention (approved option "Stop after a few tries"). A resumed run rechecks only lines nobody saw: the ids the partial run listed are kept in the connection's settings (approved option "Remember seen lines").

**Decided by the owner, 2026-11-11:** the sync stops retrying after 3 failed runs in a row on a repeated page token (approved option "3 runs").

**In #1128:** a resumed window keeps the ids its partial runs listed (`settings.resume_listed`, at most 2,000; over that the list is dropped, not cut), and the run that finishes rechecks only lines neither run listed. After 3 runs in a row on a repeated page token (`mercuryRepeatedPage`, `settings.repeated_page_runs`) the cron and an unforced run skip the connection; the owner's own refresh still runs it, and a success or a reconnect clears the count. **Left:** the stopped connection still reads as connected; the app has no persistent problem state for it (showing one is a UI change; marking only the third failure needs a new `last_error` code).

**Decided by the owner, 2026-11-11:** a connection whose last sync ended on the page cap shows a warning on its row, with the existing sentence, from the first failure (approved option "Warn from 1st failure"). No database change and no new wording.

**In #1131:** a connection whose last sync ended on the page cap shows the existing sentence as a warning on its row in the Mercury list and on its own page (`mercuryProblem`), from the first failure; the refresh stays. **Left:** the Settings › חיבורים row still reads connected (a short status word there would be new wording).

**Decided by the owner, 2026-11-11:** the warning says what happened, in a new sentence (approved option "New accurate sentence"): "הרענון מ־Mercury נתקע. נסו שוב מאוחר יותר, ואם זה חוזר פנו לתמיכה." The old sentence ("too many lines for one refresh") was untrue for this case: a long list is read over several runs and shows nothing. It replaces the sentence for `sync_page_cap` everywhere, the refresh's toast included.

**Decided by the owner, 2026-11-11:** the Mercury list row keeps the full sentence (approved option "Keep the full sentence").
