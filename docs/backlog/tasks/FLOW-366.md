**Month lines**
- [ ] Entry from Home's נכנס or יצא row; header "← בית", then a נכנס | יצא switch so the owner flips without going back.
- [ ] Summary: the direction's month total (the same figure as Home's row), "N תנועות · N ממתינות לאישור · $X לא נספרים ברווח".
- [ ] Organize chips, always visible (side-scroll if needed): לפי תאריך (default, grouped by day with a day total), לפי סכום (largest first), לפי פרויקט, לפי קטגוריה (grouped with a total per group, largest group first). One is always selected; no filters.
- [ ] Sticky header (FLOW-363's compact panel): past 190px a compact bar slides down (240ms): "← בית", "יצא · $X", and one row with the נכנס | יצא switch and the chips. Day or group heads stick under it.
- [ ] Row: supplier, "project · category", amount; a tag only when it matters: ממתין לאישור (amber) or "… · לא נספר ברווח" (accent). No project: "בלי פרויקט".
- [ ] A row pushes the transaction page in from the left; back reads "← יצא" (or נכנס).

**Transaction page**
- [ ] Top bar fixed with Back; after 110px it takes the surface colour and shows "<supplier> · <amount>" (200ms fade).
- [ ] Header: status (מאושר / ממתין לאישור), supplier 24/600, amount 40/400, "date · direction · source" 14. A pending line shows the banner "השורה מחכה לאישור שלך · לאישור", which opens the review queue on that item.
- [ ] Icon rows: פרויקט and קטגוריה open the pickers (the review queue's sheet); פיצול is one row that opens FLOW-370.
- [ ] Recurring: one row whose value is the pace (לא קבוע / כל חודש / כל חודשיים / כל רבעון / כל שנה) with "בערך ב־N לחודש · זוהה לבד / סימנת"; it opens the כל כמה זמן sheet, which says it applies to every payment of that supplier (per supplier and currency, [0172](../../decisions/0172-recurring-charges.md), [0175](../../decisions/0175-recurring-pace-dismissals.md)).
- [ ] History, only when recurring with history ([0178](../../decisions/0178-party-charges.md)): "בדרך כלל $X · עלה/ירד ב־N%" (signal colour only when it hurts: an expense up or income down), a 6-month bar chart (past on the right, this month highlighted), the last 3 payments, and לכל החיובים / לכל התקבולים under the title חיובים קודמים / תקבולים קודמים.
- [ ] לכל החיובים sheet: "<supplier> · כל החיובים", context "<project> · <category> · 12 האחרונים" (0178's context rule), "בדרך כלל $X · 12 חודשים · $total", 12 rows newest first (date, amount; ±20% or more shows ▲/▼ %, signal colour when it hurts; the current line marked השורה הזו). A row opens that charge.
- [ ] נספר ב: one summary row ("רווח ותזרים"); it turns accent with the reason when something is off, and opens the sheet with the switches נספר ברווח and נספר בתזרים.
- [ ] Footer: Jev's note on how it was classified, the document when there is one, the bank account and the raw bank description. Each change shows the undo toast.
- [ ] Loading and empty: use the shared skeleton, empty state, inline spinner and sync strip of [FLOW-371](FLOW-371.md).
- **MCP:** existing tools cover every write (`assign_expense`, `set_expense_category`, `set_line_pace`, `set_line_recurring`, `set_line_pnl`, `set_line_cash`, `undo`) and read (`get_cash_lines`, `get_line_charges`, `get_line_recurring`). If the lines read needs the group totals by project or category, add them to `get_cash_lines` and TOOLS.md.
- [ ] From the FLOW-363 (2c) pixel review: on an income transaction, the earlier-payment rows under "תקבולים קודמים" draw "₪5,000" neutral with no "+"; income rows get "+" and green like every other income figure (decision 0181).
- **Acceptance:** stories of the lines in each of the 4 orders, scrolled with the compact panel, and the transaction page pending, not in profit, and recurring with a +27% change, plus both sheets, at 320 and 393 with invented lines that add up to the summary; a sample test that the listed rows add up to the summary and to Home's row; a unit test that the change colour follows "hurts" for expense and income; an e2e that a row opens the page and Back returns to the same scroll; design review against the boards.
- **Design spec:** the counted-in row and sheet are written down in [implementation-guide §7.10](../../../design/system/implementation-guide.md) (FLOW-363 (4)). The code is built here, for the transaction line.
