# FLOW-1310 · Perf: loan outlooks in the database
- **Type:** MEDIUM (perf) · **Status:** done (#1284) · **Source:** the FLOW-1275 [plan](../../tech/flow-1275-server-side-math.md), slice 10 (owner approval 2026-11-24).
- **Files:** a migration (`public.loan_outlooks`) and pgTAP with vectors from `loan-outlook.test.ts` and `loans-paid.test.ts`. No app change (FLOW-1316 switches the app).

`public.loan_outlooks(p_today date default null)`, security invoker: per open loan the next payment (date and parts), the next 12 months' and the rest's totals, the end date and the late date (FLOW-1258's rule), from `loan_schedule_rows`, `loan_balances`, `loan_unsplit_payments` and the last paid day. The rest of each schedule is built from the balance on each read, about 1.6 ms a loan, about 35 ms for Flow QA's 22 loans.

- [x] The read and its vectors; another company's member gets nothing. `private.loan_outlook_build(jsonb)` is the pure core (the vectors run through it and through the app's builders); `public.loan_outlooks(p_today)` gathers and calls it. The answer is `[{ loan_id, next: { due_date, interest_minor, escrow_minor, principal_minor, amount_minor }, ahead_minor, to_end_minor, end_date, late_on }]`, absent = null: a loan with neither a next payment nor a late date is left out. Measured locally: about 34 ms and 285 B a loan for 22 loans.

**Acceptance:** every vector equal; about 40 ms warm for Flow QA as its owner, read-only, reported.
