# FLOW-365 · Redesign: the review queue (לאישור) without a tab
- **Type:** UI (design approved) · **Status:** ready · **Depends on:** [FLOW-363](FLOW-363.md), [FLOW-364](FLOW-364.md) · **Related:** [FLOW-439](FLOW-439.md) (the card or account name on the card's source line) · **Source:** the owner's approved redesign, handed off 2026-10-11. Design: [Design canvas](https://claude.ai/artifact/9grt9spjshVCxerYWrRXiD), page "Ready for dev", section "Review queue" (boards: prototype, project picker, no suggestion yet, all items, all done, split from the card, card after the split); rules on "Design guide", motion on "Flow & motion".
- **Files:** `app/src/screens/review-screen.tsx`, `app/src/screens/review-queue.tsx`, `app/src/screens/review-shared.tsx`, `app/src/screens/review-skipped.tsx`, `app/src/screens/jev-review-card.tsx`, `app/src/screens/change-form.tsx`, `app/src/ui/review-card.tsx`, `app/src/ui/review-count.tsx`, `app/src/ui/action-bar.tsx`, `app/src/ui/change-sheet.tsx`, `app/src/ui/change-picker.tsx`, `app/src/ui/card-swipe.tsx`, `app/src/ui/css/06-review-card.css`, `app/src/ui/css/14-review-change.css`, `app/src/ui/css/17-action-bar.css`, their stories and tests.
- [ ] Entry from Home's דורש טיפול ("<n> פריטים ממתינים לאישור"); the header starts with "← בית". A link that opens one item (from a transaction's "לאישור", or a project's דורש טיפול filtered to the project) opens the queue on that item or filter.
- [ ] Header: title לאישור, "פריט i מתוך n", a segmented progress bar (done accent, current dim accent, rest track), "<n> אושרו אוטומטית היום", and "הצגת הכול" for the flat list.
- [ ] Card, top to bottom: source (חשבונית מצולמת, or שורת בנק · <bank>, with FLOW-439's card name when it has landed), supplier, date · הוצאה/הכנסה, the document thumbnail (photos only, opens the viewer), the amount (income green with +), then two big rows פרויקט and קטגוריה, each tagged הצעה / בחרת / חסר, and Jev's one-line reason under them.
- [ ] Split from the card (approved 2026-10-15): under the project and category box, a text link with the split icon, "פיצול לכמה פרויקטים או קטגוריות" (15/400, accent, 44px tall); hidden for a transfer. It pushes in [FLOW-370](FLOW-370.md)'s split screen from the left (280ms; back 220ms) with this line (supplier · dd/mm · category, the amount); the rest stays on the suggested project and category. After saving, the box becomes a split summary: "פיצול · N חלקים · $total" with עריכה, one row per part (project, category, amount) and the rest row; toast "הפיצול נשמר · N חלקים". שינוי then opens the split editor; אישור is enabled and its line reads "אישור שומר את הפיצול: כל חלק נספר בפרויקט ובקטגוריה שלו". הסרת הפיצול in the editor brings back the single project and category. A split doesn't create the "לזכור לספק" rule.
- [ ] Actions in a fixed bar in the thumb zone: אישור (wide, primary), שינוי, דלג, with one line under it on what happens.
- [ ] No suggestion: the project row reads "אין הצעה · הקישו לבחירה" in accent, אישור is disabled, the line says "בחרו פרויקט כדי לאשר".
- [ ] Transfer: the project row says it doesn't apply; אישור marks the line as a transfer (out of profit and cash).
- [ ] Picker sheet: search, a list with the suggestion marked, + פרויקט חדש, and the "לזכור לספק …" switch (on by default). Picking saves that field only and returns to the card ([FLOW-831](FLOW-831.md)'s שמירה rule applies to the change sheet, not to this one-tap pick).
- [ ] Approve or skip: the card leaves to the right (240ms, ease-exit), the next one comes in from the left; toast "הפריט אושר · ביטול" for 3s. דלג sends the item to the end of the queue.
- [ ] Last item: the "הכל מאושר" screen with what was done and "חזרה לבית".
- [ ] The review tab and whatever only it used are removed.
- [ ] Loading and empty: use the shared skeleton, empty state, inline spinner and sync strip of [FLOW-371](FLOW-371.md).
- **MCP:** the existing `list_review`, `assign_expense`, `assign_expense_split` and `undo` cover approve, change and undo. Skip-to-end needs a write the queue can replay: if the order is only on the device, say so in the PR; if it is stored, add `skip_review` (idempotency key, rate limit, undo) and list it in TOOLS.md.
- **Acceptance:** stories for the card with a suggestion, no suggestion, a transfer, a photo with a thumbnail, the picker sheet, a split card and the done screen, at 320 and 393 with invented suppliers and round amounts; a unit test that אישור is disabled without a project; a test that דלג moves the item to the end; a test that the toast's ביטול restores the item; a test that approving a split card saves every part and the rest, and that the vendor rule is not created; reduced motion swaps cards without sliding; design review against the boards.
