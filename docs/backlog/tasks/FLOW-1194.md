# FLOW-1194 · Perf: Company profit's "by category" order loads category lines on scroll; search finds every line
- **Type:** MEDIUM (perf) · **Status:** ready · **Source:** the perf steward's daily diff review, 2026-11-14 ([report](../../qa/perf/2026-11-14.md), finding 9).
- **Files:** `app/src/use-company-profit.ts`, `app/src/screens/company-profit-screen.tsx` and their tests.

In the "by category" order, the first view shows collapsed category rows, with each count and amount from the two breakdowns. Yet one `get_breakdown_lines` loop runs per category, all categories in parallel (`use-company-profit.ts:290-296`), each paging 40 rows a call in sequence (`:223-242`). That is about 20 calls for a month with about 20 categories. The count comes from the code path, not a trace.

The owner was asked first, because users could see a short load.

**The owner's answers, 2026-11-14.** To the card "Company profit's \"by category\" order loads every category's lines up front, even though they start collapsed: about 20 extra reads for a month with ~20 categories. Loading a category's lines only when you tap it would make the screen faster, but a short loading row shows each time a category opens. Do you want that?", the owner first chose "Load on tap (Recommended)", then wrote: "Load on scroll" and "And the search ahould include them also". Then, again: "Load on scroll".

- [ ] Entering the "by category" order reads no lines. A category's lines are read as its row scrolls into view, so they are usually ready before it is tapped. If a tap comes first, the lines are read on the tap, with a short loading row.
- [ ] The date and amount orders read all lines with one paged read and a larger page, not one loop per category.
- [ ] Search includes lines not loaded yet. Every search that can show a month's lines asks the server, never only the rows already loaded. The app's search screen already reads the server (`search_transactions`); a test pins that a line from an unloaded category is found. Company profit has no search field today. The builder confirms with the owner whether one is meant there before adding one.

**Acceptance:**
- Entering the category order reads no lines. Scrolling a category into view reads its lines once.
- A line in a category that never scrolled into view is found by search.
- The PR's traces show the before and after.
