# FLOW-1194 · Perf: Company profit's "by category" order loads a category's lines when it opens
- **Type:** OWNER DECISION (perf) · **Status:** needs-owner · **Source:** the perf steward's daily diff review, 2026-11-14 ([report](../../qa/perf/2026-11-14.md), finding 9).
- **Files:** `app/src/use-company-profit.ts`, `app/src/screens/company-profit-screen.tsx` and their tests.

In the "by category" order, the first view shows collapsed category rows, with each count and amount from the two breakdowns. Yet one `get_breakdown_lines` loop runs per category, 40 rows a call, in sequence (`use-company-profit.ts:193, 223-242, 290-296`). That is about 20 calls for a month with about 20 categories. The count comes from the code path, not a trace.

The fix: read a category's lines only when it opens, and give the date and amount orders one all-lines read with a larger page. Users would see a short load when they open a category, so the owner decides first.

**Acceptance:** the owner's answer is quoted here. If built: entering the category order reads no lines; opening a category reads its lines; and the PR's traces show the before and after.
