# FLOW-1063 · A project's forecast takes as many added lines in one category as the owner wants
- **Type:** UI · **Status:** in-progress (#1005)
- **Files:** `app/src/project-next-edit.ts` (`categoryChoices`, `forecastCategoryIds`), `app/src/project-next-edit.test.ts`, `app/src/screens/project-next-edit-screen.tsx` (the `inForecast` input), its stories and tests, `app/src/screens/recurring-screen.tsx` only if the הוספת קבוע link needs a change, a decision file, a design log entry, a changelog fragment.
- **Source:** the owner, 2026-11-06, from the phone: on קבועים with the הכנסות filter, הוספת קבוע opened the add sheet, and "הכנסות שכירות" was not in the category picker for 510 Green Gables, so no rent income could be added. The picker leaves out every category the project's forecast already counts (`forecastCategoryIds`), and that project already has one recurring rent income (DHA S8 HAP CKS, $2,771, category הכנסות שכירות). The owner's word: "There is a 2 payment for the same category we can't allow only one, the user should be able to add as many as he want."

- [x] The category picker offers every usable category, including the ones the project's forecast already counts; a category the forecast already has keeps its place (suggested or the rest, by the existing rule) and its hint says so in the repo's voice, with the forecast's amount for it when there is one (for example "כבר בצפי · $2,771"), so the owner sees the second line is a second line. The hidden, loan-principal and kept-out-of-profit exclusions stay.
- [x] Two added lines in one category live side by side: each `add` edit already has its own id (`add:<id>` row keys, no unique index for `kind = 'add'`), so this is a check, not a change: a story and a test where the forecast has a recurring income in a category and the owner adds a second line in it; the next-month page then lists both, and removing one leaves the other.
- [x] Picking an income category still flips the new line to an income (sign, "הכנסה קבועה בצפי", the meta line), as today; a test covers the picker offering an income category that is already in the forecast.
- [x] `forecastCategoryIds` and the `inForecast` input go if nothing else uses them (CONTRIBUTING: remove what the change leaves unused), or stay only for the hint.
- [x] A decision file `docs/decisions/0259-many-forecast-lines-per-category.md` (the owner's word above, 2026-11-06; name the decision or log entry that set the one-per-category rule if there is one: look in `docs/design/log/2026-11-01-flow-1005.md`, `docs/backlog/tasks/FLOW-446.md`, `docs/decisions/0240-*.md` and `0243-*.md`), plus the README row; a design log entry `docs/design/log/2026-11-06-flow-1063.md`; a changelog fragment `docs/changelog.d/2026-11-06-flow-1063.md`.
- **Acceptance:** on a project whose forecast already has a line in הכנסות שכירות, the add sheet offers הכנסות שכירות with a "כבר בצפי" hint; adding a second line there saves it as an income next to the first; both show on the project's next-month page and on Home's expected rows; unit tests, the story tests of the add sheet in both themes, lint, typecheck, the unused-code and CSS-token checks pass.
