# FLOW-1229 · Perf: the project page's forecast reads start when the project lands, not after two more reads
- **Type:** SMALL (perf) · **Status:** in-progress (#1217) · **Source:** the perf steward's re-measure after #1216's deploy, 2026-11-18. On the FLOW-804 phone profile against production, an in-app visit to `/projects/:id` settled at 2.9 to 5.7 s (decision 0230: 0.5 s). The forecast's seven reads began at 4785 ms.
- **Files:** `app/src/screens/project-detail-screen.tsx`, `app/src/next-month-for-project.ts`, `app/src/next-month-for-project.test.tsx`, `app/src/screens/project-page-forecast-start.test.tsx`.

The chain, in ms from navigation: the lifetime `get_project` (every period) answered at 4029; only then did the forecast mount (`forecastLive` needs `lifetime.data`), whose overhead-project check read `/companies` (4090 to 4715) and kept the project's own reads off (`deciding`) until it answered; the reads began at 4785. None of the forecast's reads takes the currency that the lifetime read supplies, and the overhead answer is already in the project's own read (`is_overhead`, the same `companies.overhead_project_id` test).

- [x] The forecast's reads start once the project's own read has landed (FLOW-804's deliberate deferral kept), not after the lifetime read; only the figure waits for the lifetime read.
- [x] `useProjectNextMonth` takes the page's own `is_overhead` as a hint that only starts reads early: a false hint starts the project's own reads and a true one the company's, beside `/companies`. What is shown is still decided by the `/companies` answer (or its failure fallback), and the row stays loading until then; a stale hint costs extra reads, never a different figure. A cached error on the shared forecast reads (overrides, categories) shows once the overhead answer lands instead of immediately; the final state is unchanged. While that answer is out the hook also returns empty data fields where a disabled read could hand back cached data; no consumer draws them while pending.
- [x] Tests: the reads start while the lifetime and company reads are out (project and overhead project); the row shows no figure from a hint; a stale hint never shows the project's own figure before the answer.
- [ ] Not done here: the lifetime `get_project` itself takes about 3.9 s on the phone profile, so the forecast's figure still settles when it lands (proposal in the PR).

**Acceptance:** with the lifetime read held back, the forecast's reads go out when the project's own read lands; the page shows the same rows and figures; the tests pass.
