# FLOW-1197 · Bug: a hard-money loan's renovation draws count twice in a renovation's purchase price
- **Type:** BUG · **Status:** in-progress (#PR) · **Source:** the owner, 2026-11-14, on a renovation's net profit.
- **Files:** a new migration patching `get_property_returns`, `supabase/tests/database/property_returns.test.sql`, `supabase/functions/flow-mcp/tools_property.ts`, `docs/mcp/TOOLS.md`, decision 0269.

A loan paid out at closing with no closing amount set counted its whole principal into the purchase price (0250). A hard-money loan's draws reached the bank and paid the renovation, which rehab already counts, so the net profit read the draws twice.

- [x] With no closing amount set, the price counts the principal less the loan's draws (decision 0269); a closing amount set still wins.
- [x] `taken_over_loans` names `draws_minor`; the MCP description and TOOLS.md say so.
- [x] pgTAP: draws before the first rent count; a renovation refund, a deposit after the first rent and money after the payoff do not; a closing amount set wins.
