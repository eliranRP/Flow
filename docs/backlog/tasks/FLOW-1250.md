# FLOW-1250 · Perf: an optimistic write refreshes each cached answer once, not twice
- **Type:** SMALL (perf) · **Status:** in-progress (#PR) · **Source:** the perf steward's 2026-11-22 [report](../../qa/perf/2026-11-22.md), diff review (load scope), row 1. Found on FLOW-1244's group move (#1237).
- **Files:** `app/src/use-write.ts`, its tests.

With `optimistic` set, `useWrite` refreshes its `keys` and then each snapshot key as well (`use-write.ts`, the success path). When a snapshot key already sits under one of `keys`, the second invalidate cancels the first fetch and starts another, but the first request has already gone out. On FLOW-1244's group move that is one extra `get_project` per key on screen (two on the project page, 12.5 KB and about 70 to 85 ms in the database each). Ten app files use `optimistic:`.

- [x] Skip a snapshot key that one of `keys` already covers (by prefix, as `useInvalidateBooks` matches), so each cached answer is fetched once.
- [x] Tests: an optimistic write whose snapshot sits under its keys sends one request per active query; one whose snapshot sits outside them still refreshes it.

**Acceptance:** one request per active query after an optimistic write; every caller's behaviour is otherwise unchanged; the tests pass.
