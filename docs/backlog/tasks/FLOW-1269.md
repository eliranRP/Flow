# FLOW-1269 · Perf: read the main screens in the background once Home has settled
- **Type:** MEDIUM (perf) · **Status:** blocked (FLOW-1267: it fills the cache FLOW-1267 keeps; FLOW-1273: both change `screen-loaders.ts`) · **Source:** decision [0271](../../decisions/0271-half-second-by-kept-data-and-one-wave.md) (owner, 2026-11-23); the perf steward's split of 2026-11-23.
- **Files:** `app/src/App.tsx` (beside `preloadScreens`), `app/src/screen-loaders.ts`, a new `app/src/background-reads.ts`, the screens' query-option exports, tests.

Decision 0271, item 2: the owner chose "Yes, main screens" (2026-11-23). Today only code is preloaded after Home (`preloadScreens`, after `whenReadsSettle` plus idle, App.tsx:105-126); data is read on the tap, except the project page on pointerdown (`PrefetchProjects`) and Review's list beside its chunk.

- [ ] After Home's reads settle and the phone is idle (the same signal `preloadScreens` waits for), prefetch the first-view reads of Projects, Loans, Recurring, Profit (month), Review's first page and Forecast, a few at a time, once per session. Use each screen's own query options, so a tap finds the same key warm. Where a screen's options are inline, export them only in a file no open PR claims (`project-detail-screen.tsx`, `company-profit-screen.tsx` and the Review files belong to FLOW-1270 to FLOW-1272 while those are open); otherwise wait for that PR.
- [ ] Skip when `navigator.connection.saveData` is on or `effectiveType` is `2g`/`slow-2g`; skip what is already fresh in the cache (`staleTime`).
- [ ] Never let it slow Home: it starts only after Home settles, and a tap on a screen cancels nothing but gets priority (its own read is the same key).
- [ ] Tests: the prefetch waits for settle and idle, reads each key once, honours save-data, and a later visit sends no duplicate.

**Acceptance:** after Home settles, a tap on any main screen finds its first-view data in the cache; Home's own time does not grow; the gates pass.
