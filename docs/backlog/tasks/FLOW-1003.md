# FLOW-1003 · A removed forecast row stays out the next months
- **Type:** SMALL DB · **Status:** claimed (UI lane 1, 2026-11-01, claude/flow-remove-sticks) · **Source:** the owner, 2026-11-01: "every month I need to remove again the forecast items… when I remove once it does not return to the forecast next month", and "it should be affected now as well after I did it for the current month". Decision [0239](../../decisions/0239-forecast-removal-sticks.md).
- **Files:** `supabase/migrations/20261101070000_forecast_removal_sticks.sql` (new), `supabase/migrations.lock`, `supabase/tests/database/project_forecast_edits.test.sql`, `app/src/project-forecast-writes.ts`, `app/src/screens/project-next-edit-screen.tsx`, `app/src/dev/project-next-month-sample.ts`, `supabase/functions/flow-mcp/tools_specs.ts`, `docs/mcp/TOOLS.md`, decision 0239, a design log entry, a changelog fragment.

- [x] A removal is written on pace `month` from its month: the row stays out of every later month until החזרה.
- [x] The removals already made become `month`, so the rows the owner removed for November stay out of December.
- [x] Removing a row that is already out (for its month or an earlier one) writes nothing.

**Acceptance:** after a removal for this month, `project_forecast_edits_for` lists it for a month a year later; a removal for next month of the same row returns an empty undo; a restore brings it back.
