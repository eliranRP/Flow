# FLOW-1311 · Perf: category months kept current on write (only if the forecast read needs it)
- **Type:** LARGE (perf) · **Status:** blocked (FLOW-1307) · **Source:** the FLOW-1275 [plan](../../tech/flow-1275-server-side-math.md), slice 12 (owner approval 2026-11-24).
- **Files:** a migration (`public.category_month_sums`, its RLS, `private.category_month_sums_rebuild`, deferred statement-level triggers, `private.project_category_months_lean` reading it); pgTAP parity per write path and a dependency test; a line in CONTRIBUTING's migration rules.

Built only if FLOW-1307's measured read is over its 300 ms budget; otherwise closed unbuilt. Today `private.project_category_months_lean` takes 60 ms for Flow QA's 14 projects on every inputs call; one project's recompute is 24 ms warm, 47 ms cold (read-only, as Flow QA).

- [ ] The table holds every month by company, project, category and currency; the read picks the window from `p_today` (no midnight job).
- [ ] The trigger list is derived from what `private.pnl_lines` depends on (`pg_depend`: today `accounts`, `allocations`, `categories`, `companies`, `legs`, `transactions`) and what `project_category_months_lean` reads (`transactions`, `private.split_parts`, `review_queue`, `allocations`, `categories`, `private.loan_parts`); a pgTAP test lists the dependencies and fails on one with no sums trigger.
- [ ] The write paths of the plan's section 3, among them `legs` updates (`journal_entry_update` moves legs between transactions), `review_queue` inserts and deletes as well as status changes, and `transactions` only on the columns that change a sum (production has about 74 transaction updates an hour, mostly sync); a deferred constraint trigger rebuilds the collected keys once per transaction.
- [ ] A migration or backfill that disables triggers (`alter table ... disable trigger`, `session_replication_role = replica`) must end by calling `private.category_month_sums_rebuild` for the companies it touched; CONTRIBUTING says so, and the daily report's read-only parity check catches one that does not.
- [ ] pgTAP: after each kind of write, the table equals the aggregate for every fixture project.

**Acceptance:** the inputs and forecast reads answer exactly as before and faster (measured as Flow QA, read-only); the write paths' added time measured on a local database (a 200-line sync, a split, a review answer, a category switch).
