# FLOW-1116 · Plan: Home's figure reads leave from the page itself, before the app's code arrives
- **Type:** PLAN FIRST (perf) · **Status:** plan-first · **Source:** the perf steward's daily report ([2026-11-09](../../qa/perf/2026-11-09.md)); the owner's pick 2026-11-09: "Plan it first".
- **Files:** to be named by the plan; likely `app/index.html` or a small inline script, `app/src/home-early-reads.ts`, the security headers (CSP).

Since FLOW-1115, a cold start on Home sends its two figure reads (`cash_months`, `get_dashboard`) once the app's code has loaded and run its first module: the first read at about 0.8 s on the FLOW-804 phone. The page itself arrives at about 0.15 s and the code at about 0.55 s. A small script in the page could send the two reads at about 0.2 s and hand their answers to the app, which could save about another 0.5 s on a cold open (not measured).

The plan, for the owner before any build:
- How the script reads the saved session without the Supabase client: an expired access token, the refresh, and a session that belongs to another user.
- The company header (`x-flow-company`) and the shown company, as the app sends them.
- How the answers reach the query cache with Home's keys, and what happens when a read fails or arrives late.
- The CSP: an inline script needs a hash or nonce (decision 0192).
- How it is measured: the steward's local A/B of cold Home on the FLOW-804 phone, and the same read count.
