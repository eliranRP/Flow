# FLOW-1145 · Home's first load leaves out the other screens' skeleton blocks
- **Type:** SMALL CYCLE (perf) · **Status:** done (#1112) · **Source:** the perf steward's daily pass, 2026-11-10; the owner's pick 2026-11-10: "Load skeletons later".
- **Files:** `app/src/cold-open.tsx`, `app/src/cold-open-blocks.tsx` (new), `app/src/cold-open-route.test.tsx`, `app/src/cold-open-blocks-fail.test.tsx` (new).

Home's entry grew from 242.1 to 247.1 of 248 KB gzip in a day, mostly with FLOW-1140 (#1102): a cold open draws its route's own loading frame, so every screen's skeleton (`ui/screen-skeletons.tsx`, `ui/loading-shapes.tsx`) loaded with Home. Less than 1 KB was left, so the next change to Home would turn main red.

- [x] The route frame's grey blocks (`ColdOpenBlocks`) move to their own file. A frame starts reading it when it draws, and the blocks wait 300ms before they show (as before), so the file loads during that wait. The bar or band, and Home's own skeleton, stay in the entry and draw on the first frame as before. A failed read draws no blocks and keeps the bar; the next frame tries again.
- **Acceptance:** `pnpm check:bundle`; the cold-open tests (the bar on the first frame; the blocks after the wait; a failed read keeps the bar).
- **Measured:** Home entry 252,988 -> 251,279 bytes gzip (−1.7 KB); all JavaScript +1.0 KB (its own chunk).
