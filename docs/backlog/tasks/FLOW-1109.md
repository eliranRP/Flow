# FLOW-1109 · Make room in Home's code so the bundle limits go back to 248 / 680 KB
- **Type:** SMALL CYCLE (perf) · **Status:** done (#1057, deployed with b76cb23) · **Source:** the perf steward's daily report ([2026-11-08](../../qa/perf/2026-11-08.md)); the owner's pick 2026-11-07 for the bundle budget: "Trim first" (cut or lazy-load code before raising a limit; raise only if trimming can't make room, and tell the owner).
- **Files:** `app/src/ui/icons.tsx`, `app/src/ui/icons-later.tsx` (new), `app/src/txn-nav.tsx`, `app/src/txn-step-nav.tsx` (new), `app/src/setup/copy.ts`, `app/src/setup/model.ts`, `app/src/setup/home.tsx`, `app/src/setup/shell.tsx` and two setup tests, the import lines of the moved icons' and hooks' users, `scripts/bundle-budget.json`.

#1052 (2026-11-07, the builder's default, owner to confirm) raised the Home entry 248 -> 252 KB and all JavaScript 680 -> 700 KB to unblock main's deploy. That came after the owner's pick, which asks for a trim first. On `db54ff3` the Home entry is 247.9 / 252 KB gzip and all JavaScript 680.0 / 700 KB: both fit the old limits, but only by 143 bytes (253,809 of 253,952) and 32 bytes (696,288 of 696,320), so the next change would push them over again.

The entry chunk (`index-*.js`, 204.2 KB gzip; its stylesheet is 43.7 KB), by source module, raw bytes from its source map: react-dom 202 KB, @supabase/auth-js 97 KB, react-router 38 KB, @tanstack/query-core 33 KB, postgrest-js 16 KB; then app code, the largest being `ui/icons.tsx` 12.5, `ui/list-row.tsx` 11.8, `screens/HomeScreen.tsx` 10.9, `screens/home-activity.tsx` 9.1, `App.tsx` 8.0, `ui/toast.tsx` 7.9, `screens/home-parts.tsx` 7.7, `screen-loaders.ts` 7.6, `use-books.ts` 6.5, `ui/sheet.tsx` 5.8 KB. Leads to check, each one only if Home doesn't draw it before first paint:

- `screens/month-drawer.tsx` (2.7 KB), opened by a tap on Home.
- The setup modules (`setup/storage.ts` 3.2, `setup/copy.ts` 2.5 KB), reached through `setup/home.tsx` (the completed toast) and `App.tsx`'s setup routes.
- `team-api.ts` (2.9 KB) through `team-queries.ts`: likely out, since Home's header draws `<CompanySwitcher>` at first paint and `use-is-viewer.tsx` (`useHoldWrites`, `useHoldOwnerSettings`) reaches it too.
- `screens/SignInScreen.tsx` (2.3 KB): only a signed-out start draws it.

**The cause found:** Home's entry is one chunk for everything it loads up front (`vite.config.ts`, the `$initial` group), and a module in that chunk keeps every export any later screen uses. So a file Home needs one thing from brings the rest along: `setup/copy.ts` came whole (every setup screen's text) for one toast string and the step count, `ui/icons.tsx` with all 63 icons for the 26 Home's first load draws, and `txn-nav.tsx` with a card's list steps for the four list helpers Home uses.

- [x] Room under the old Home limit, with nothing Home draws at first paint moved out of its entry. Each split moves only code no module of Home's first load uses: the step count to `setup/model.ts` and the toast string to `setup/home.tsx`, 37 icons to `ui/icons-later.tsx`, and `useTxnNav` and the hooks around it to `txn-step-nav.tsx`. The Home entry goes 253,809 -> 247,606 bytes gzip (−6.1 KB); about 6 KB of room under 248 KB.
- **All JavaScript:** grows 1.1 KB (696,288 -> 697,383 bytes), since the moved code now loads as its own chunks, so it is over the old 680 KB and stays at 700 KB, which the owner hears of. The month drawer, the setup storage, team-api and the sign-in screen were not moved: the first two lead nowhere big, team-api is drawn by Home's header, and the sign-in screen is a signed-out start's first paint.
- [x] `scripts/bundle-budget.json`: the Home entry goes back to 248 KB; all JavaScript stays at 700 KB; the reason in the file.
- **Acceptance:** `pnpm check:bundle`; `node scripts/load-report.mjs --speed 7` no slower; a tap on what moved is no slower on the FLOW-804 phone.
