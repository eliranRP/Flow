# FLOW-1259 · Perf: Home's late row does not wait for browser idle time
- **Type:** SMALL (perf) · **Status:** done (#1255) · **Source:** the perf steward's 2026-11-23 [report](../../qa/perf/2026-11-23.md), diff review (load scope), row 1. Follows FLOW-1254 (#1250).
- **Files:** `app/src/screens/HomeScreen.tsx`, `app/src/forecast-skip.ts`, their tests.

Since FLOW-1254 the late row waits for `forecast_overrides_for` so it draws once. But on the current month that read still starts only after first paint (`useLateBillsQuery(isCurrent, isCurrent && afterPaint, isCurrent && showBooks)`), and `useAfterFirstPaint` waits for `requestIdleCallback` with a 1,500 ms timeout. So the late row can appear up to about 1.5 s after the rest of Home, plus one round trip. `missing_bills` already starts at mount, and the month forecast reads the overrides under the same key, so starting it at mount costs no extra request.

- [x] On the current month, start the overrides read together with `missing_bills` (at mount); another month still reads neither (FLOW-1252).
- [x] Tests: on the current month both reads start at mount and one `forecast_overrides_for` request is sent; the late row draws once.

**Acceptance:** Home's late row no longer waits for idle time; no request is added; the tests pass.
