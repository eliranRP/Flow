# FLOW-1101 · A failed investment save after a new project's create makes a retry create a second project
- **Type:** BUG · **Status:** in-progress (#1047) · **Depends on:** none
- **Source:** review r1 of #1039 (FLOW-1093), UX rules review 2026-11-07. Found in `project-form-sheet.tsx`; it predates FLOW-1093 and also hits the Projects screen.
- **Files:** `app/src/screens/project-form-sheet.tsx` and its test.

- [x] When `upsert_project` succeeds and `set_project_investment` then fails, the sheet stays open and a retry calls `upsert_project` again with no id, so a second project is made. Keep the new project's id after the first write and retry only the investment (or make the create idempotent), and say on failure that the project was created.

- [x] Open (review r2 of #1043): a sheet closed after a failed figures save still has the project made, but its id is gone with the sheet. Reopening "פרויקט חדש" (from the Projects tab or the picker's "+ פרויקט חדש") makes a second project. Decide whether the picker keeps the id, or the figures retry is offered on reopen; then test it.
  Done (the owner's decision, 2026-11-07): a close after the figures failed counts as "created without figures". The sheet runs the create's own success (the picker's `onCreated` assigns the line; elsewhere the project's page opens), shows "הפרויקט נוצר בלי הנתונים. אפשר להוסיף אותם בדף הפרויקט." and drops the id. Each open is a fresh form keyed on an open count, so a reopen (also during the close animation) starts empty with no id. Tests: ✕ after the failure calls `onCreated` once with no second upsert; a reopen starts empty and creates with no `p_id`.

**Acceptance:** a test where `set_project_investment` fails once: the retry makes one project in total and saves its figures.
