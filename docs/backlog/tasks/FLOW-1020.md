# FLOW-1020 · Review's first page is read on the tap, not after its code loads
- **Type:** SMALL CYCLE (perf) · **Status:** ready · **Source:** FLOW-1007's "left for later"; the perf steward's report ([2026-11-02](../../qa/perf/2026-11-02.md)), decision [0230](../../decisions/0230-screens-data-in-half-a-second.md).
- **Files:** `app/src/screen-loaders.ts` or the Review route, `app/src/use-review.ts`, their tests.

Review tapped as soon as Home shows its data takes about 1.0 s at p50 on the FLOW-804 phone (2026-11-02). Its first page is 46 KB and 28 ms in the database. The read only starts once Review's code graph has loaded, so the code and the read run one after the other.

- [ ] A tap on Review starts the first page's read (`list_review_page`, 50) in parallel with its code, into the same `["review", preview]` cache, so the screen finds it in flight or done. The prefetch must stay out of Home's entry chunk (the entry is 242.3 of 243 KB).
- **Acceptance:** a unit test that the tap starts one read and the screen reuses it, no second read; the steward's before and after on the FLOW-804 phone.
