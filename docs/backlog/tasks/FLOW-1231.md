# FLOW-1231 · The project edit sheet holds the קבוצה row's place while the groups load
- **Type:** SMALL UI · **Status:** ready · **Depends on:** none
- **Source:** UX rules review 2026-11-19 (scope 5cf22eb7..c090b96a): #1220 (FLOW-1230) reads the groups only when the ⋯ button is touched or the menu or edit sheet opens. In `app/src/screens/project-menu.tsx` the edit sheet's extras render the קבוצה row only once the groups are read (`groups == null ? null : …`), and the extras sit right above the sheet's שמירה button (`app/src/screens/project-form-sheet.tsx`). On a slow line the row pops in after the sheet opens and pushes שמירה down by a row while the person may be tapping it. The same pattern existed before #1220 for a fast person; #1220 makes it likelier. Severity: Low. Rule: feedback-and-states § 2 (a placeholder holds the space the content will take); tables-and-responsive § 21 (touch targets); the owner's FLOW-1220 decision (2026-11-16: nothing moves under a finger).
- **Files:** `app/src/screens/project-menu.tsx`, `app/src/screens/project-menu-figures.test.tsx`, `app/src/screens/project-detail-screen.stories.tsx`.

If the read fails, the slot shows nothing only if it did not show a row before (so a failed read never removes a row the person sees), or a retry row; pick the smallest that keeps the height.
