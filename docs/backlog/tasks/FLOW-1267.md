# FLOW-1267 · Perf: keep the main screens' reads on the device and draw them at once
- **Type:** MEDIUM (perf) · **Status:** ready · **Source:** decision [0271](../../decisions/0271-half-second-by-kept-data-and-one-wave.md) (owner, 2026-11-23); the perf steward's split of 2026-11-23.
- **Files:** `app/src/query-client.ts`, `app/src/main.tsx`, `app/src/auth.tsx` (sign-out), `app/src/project-cache.test.ts`, `app/src/screens/books-states.test.tsx` and `app/src/screens/company-basis-sheet.test.tsx` (they import or set the cache), `app/perf/project-reopen.spec.ts` (it ages the cache's `flow-project-reads` entry; age the new store instead), a new `app/src/kept-reads.ts`, `app/src/project-cache.ts` (replaced), `app/src/company-currency.ts` and `app/src/screens/company-basis-sheet.tsx` (both import it), `app/src/use-books.ts` (its `initialData` from the project cache), tests.

Decision 0271, item 1. Today only project reads and the company currency are kept, in localStorage (FLOW-804, `project-cache.ts`, up to 6 entries of 200 KB). The query cache itself is not persisted (no persister; `staleTime` 30 min, `gcTime` 60 min in `query-client.ts`), so every new session and every screen not yet read waits for the network.

- [ ] Keep an allowlist of query keys in IndexedDB: the first-view reads of Home, Projects, the project page, Loans, Recurring, Profit (month, year, by date), Review's first page and Forecast. Nothing else: no search, no sheets, no write results.
- [ ] Key each kept entry by user and shown company (`shownCompanyUser`, `shownCompanyId`). Never restore another user's or company's entry; drop entries older than 7 days; clear all on sign-out (as `project-cache.ts` and the saved role do).
- [ ] Restore before the first render (measure the cost of waiting for IndexedDB on the phone profile; if it is too high, restore in the first moments after it and say so), check each restored entry against its read schema (`loadReadSchemas`) and drop one that fails. Bump a kept-data version when a read's shape changes on purpose.
- [ ] A restored entry is stale: the screen draws it and its query refetches at once. Expose "showing kept data, refresh in flight" per query so FLOW-1268 can draw the hint (no UI in this task).
- [ ] Replace `project-cache.ts` with this and delete it, with its tests, and the `initialData` plumbing that only it used (remove what is unused).
- [ ] FLOW-1019 (ready, unclaimed) also names `use-books.ts`; whichever is claimed second builds on the first.
- [ ] Size: cap the store (for example 5 MB) and evict the oldest.
- [ ] Tests: restore for the same user and company only; age and schema drop; sign-out clears; a restored query refetches; the project page still paints from kept data.

**Acceptance:** a repeat visit to any main screen, in a new session, draws kept data without waiting for the network; nothing is restored across users or companies, or after sign-out; `project-cache.ts` is gone; the gates pass.
