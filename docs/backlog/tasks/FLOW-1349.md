# FLOW-1349 · Perf: the kept-reads sweep fills the index, so the company list answer stops reading the whole kept store
- **Type:** SMALL (perf) · **Status:** ready · **Source:** the [2026-11-28 daily report](../../qa/perf/2026-11-28.md), diff review (load scope, row 4).
- **Files:** `app/src/kept-reads.ts` (`sweepFor`, `keepKeptReadsFor`, `keepKeptCompaniesFor`), `app/src/kept-reads.test.ts`.

When the kept rows were never indexed in a page session (boot with no user or no shown company: a first session after sign-in, a new phone), every `list_my_companies` answer reads the whole kept store with `store.all()` (`kept-reads.ts` near 307; up to 5 MB, 60 to 125 ms at CPU ×4 by the file's own note). `sweepFor` reads every row but does not fill the index, and the company list is stale after 60 s, so this recurs. On a normal boot `keepKeptReadsFor` also reads the whole store a second time beside the put-back's read, which already drops every row the sweep would.

- [ ] `sweepFor` fills the index and marks it filled.
- [ ] Skip the session sweep once the put-back has run for the same user.
- [ ] Tests: one store read per boot, and none per company-list answer after it.

**Acceptance:** one full read of the kept store per boot, in every session.
