# FLOW-370 · Redesign: one split screen for projects and categories
- **Type:** UI (design approved) · **Status:** ready · **Depends on:** [FLOW-363](FLOW-363.md), [FLOW-366](FLOW-366.md) (the transaction page's פיצול row opens it) · **Source:** the owner's approved redesign, handed off 2026-10-11. Today there are two screens (בין פרויקטים, [0169](../../decisions/0169-project-split-exact-amounts.md), and לפי קטגוריות); this is one, since every part has a project, a category and an amount. Design: [Design canvas](https://claude.ai/artifact/9grt9spjshVCxerYWrRXiD), page "Ready for dev", section "Split a payment (פיצול)" (boards: prototype from a transaction, before any part, choosing a project, more than the total, the same project twice); rules on "Design guide", motion on "Flow & motion".
- **Files:** `app/src/screens/split-screen.tsx`, `app/src/screens/line-split.tsx`, `app/src/screens/line-split-editor.tsx`, `app/src/screens/line-split-parts.tsx`, `app/src/screens/split-back.ts`, `app/src/screens/split-pop.ts`, `app/src/line-split.ts`, `app/src/line-split-copy.ts`, `app/src/project-split.ts`, `app/src/ui/radio-sheet.tsx`, `app/src/ui/split-parts-hint.tsx`, `app/src/App.tsx` (one route; `/split-category` redirects), `app/src/ui/css/12-split.css`, `app/src/ui/css/13-line-split.css`, their stories and tests; remove the second screen and what only it used.
- [ ] Top (fixed): × (back to the transaction) · "פיצול"; the line ("<supplier> · dd/mm · <category>") and the amount (28px, cents raised); a thin bar of the split so far (accent; signal when the parts pass the total) and "חולק $X · נשאר $Y" (or "חולק יותר מהסכום ב־$Z" in the signal colour). Width animates 240ms.
- [ ] Parts (cards, each slides in 220ms): "חלק N" and הסרה (toast with ביטול); project and category pickers side by side, each a short radio sheet. A project already in the split says "כבר בפיצול" and can't be picked twice; the line's own project says "הפרויקט של השורה · מקבל את השאר".
- [ ] Amount (20px, LTR) with a $ / % switch inside the field; under it the other unit ("67% מהסכום" or "= $X").
- [ ] Problems sit on the part that causes them, in the signal colour with the card outlined: "יותר מהסכום ב־$X", "הפרויקט הזה כבר בפיצול", "בחרו פרויקט", "השלימו סכום".
- [ ] "+ חלק נוסף" (dashed): a new part pre-filled with what is left.
- [ ] Rest: a quiet card "השאר · נשאר בשורה" with the line's project and category and the amount left; dims when nothing is left. The rest always stays on the line.
- [ ] "חלוקה שווה" splits the total evenly (the last part takes the cents). "הסרת הפיצול" (signal) when a split exists, with ביטול. One grey line: "כל חלק נספר ברווח של הפרויקט שלו. בבנק נשארת תנועה אחת."
- [ ] Save (fixed): "שמירת הפיצול · N חלקים" (counting the rest), disabled while any part has a problem. Toast "הפיצול נשמר" with ביטול; back on the transaction the פיצול row shows the parts.
- [ ] Loading and empty: use the shared skeleton, empty state, inline spinner and sync strip of [FLOW-371](FLOW-371.md).
- **MCP:** `assign_expense_split` (exact `amount_minor`) and `split_line` exist for the two kinds today. One part now carries both a project and a category: extend one of them (or add `save_line_split`) to take both per part, with an idempotency key, the write rate limit and undo, and update TOOLS.md; keep totals unchanged for existing splits.
- **Acceptance:** stories of the empty split, two parts, over the total, the same project twice, and an existing split with הסרת הפיצול, at 320 and 393 with invented amounts; unit tests of חלוקה שווה (cents to the last part), the over-total message, and the duplicate-project block; a pgTAP test that a saved split's parts plus the rest equal the line and the project totals don't move for an existing split; design review against the boards.
