# FLOW-516 · Notifications: this device's own row, shared switches, connected devices and a test push
- **Type:** BUG · **Status:** claimed (dev lane, 2026-10-20, fix/push-device-state) · **Related:** [FLOW-502](FLOW-502.md) (web push) · **Source:** the owner's report: turning notifications on in the iPhone Home Screen app never showed the iOS prompt; then a turn-on that stayed busy after "allow", and one that failed with no save. The owner picked the model (device row, switches for the whole account, connected devices, test push). Decision [0201](../../decisions/0201-push-device-row-and-test-push.md).
- **Files:** `app/src/push.ts`, `app/src/push-owner.ts`, `app/src/push-devices.ts`, `app/src/push-devices-sample.ts`, `app/src/push-test.ts`, `app/src/edge.ts`, `app/src/auth.tsx`, `app/src/screens/notifications-screen.tsx`, `app/src/screens/push-copy.ts`, `app/src/screens/review-push-prompt.tsx`, `app/src/screens/settings-screen.tsx`, `app/src/setup/steps.tsx`, `app/src/dev/routes/settings.tsx`, `app/src/ui/css/52-notifications.css`, `app/src/ui/ui.css`, their tests and stories, `app/e2e/notifications.spec.ts`, `app/e2e/smoke-allow.ts`, `supabase/functions/_shared/push_send.ts`, `supabase/functions/_shared/webpush.ts`, `supabase/functions/_shared/push_test_kind_test.ts`, `supabase/config.toml`, `supabase/migrations/20261020192620_push_devices_and_test.sql`, `supabase/tests/database/push_test.test.sql`, `supabase/tests/database/privilege_guards.test.sql`, `supabase/tests/database/push_notifications.test.sql`, `docs/runbooks/push.md`.
- [x] This device's row at the top of התראות: on subscribes from the tap (no await before the permission request), off unsubscribes this device only (browser and server row); blocked points to iOS Settings › Notifications › Flow on an iPhone, to the browser settings elsewhere; the Home Screen and unsupported notes stay.
- [x] The three switches are for the whole account ("מה לקבל · לכל המכשירים") and never subscribe or drop a device.
- [x] "מכשירים מחוברים": the caller's own subscriptions (`list_my_push_devices`, no endpoint or key), a readable name and when each was added, this device marked. A switch on with no device connected shows a line asking to connect this device.
- [x] "שליחת התראת בדיקה": push-send kind `test`, the user's JWT only, 5 an hour per user (`claim_push_test`), to all of the caller's devices, with a toast for each result.
- [x] Every step of a turn-on has its own timeout and reason, the browser's error name is kept, an old key's subscription is replaced by subscribing fresh with one retry after `InvalidStateError` or `AbortError`, busy always clears, and the last step shows in a muted line. The review card and setup step 7 use the same reasons.
- [x] An expired session keeps the subscription; an explicit sign-out drops it and deletes its row; another user's sign-in drops it, also after a reload.
- [x] Failed sends log the host, status and a short answer, never the endpoint.
- [ ] Follow-up: remove another device from the connected list.
- **MCP:** none: the actions are bound to the browser the person holds (0201 amends 0095).
- **Acceptance:** unit tests for the device state and every subscribe reason (mocked `Notification`, worker and `pushManager`, never-settling steps and each throw); screen tests for each state; Deno tests for the test kind (own user only, rate limit, auth); pgTAP for the new RPCs; stories; e2e on the dev route.
