# FLOW-1319 · CI: stop the runner stalls on "Wait for local Supabase" and on apt
- **Type:** CI/infra · **Status:** done (#1292) · **Source:** failed jobs on 2026-11-23 and 2026-11-24 (eight or more reported; the four runs below were re-read from their logs), each cleared by a re-run with no code change.
- **Files:** `scripts/ci-supabase-start.sh`, `scripts/ci-supabase-wait.sh` (new), `scripts/ci-apt-cache.sh`, `.github/workflows/ci.yml`, `.github/workflows/pr.yml`, `scripts/ci-supabase-start.test.mjs`, `scripts/ci-apt-cache.test.mjs`, `scripts/ci-cd.test.mjs`.

## Evidence

1. "Wait for local Supabase" ran its full 8 minutes and was cancelled: run 45337772314 job `e2e (3/4)`, run 45355355807 job `e2e (database)`, run 45363569659 job `pr (e2e 1/4)` (attempt 1 of each; the re-run passed). Across 73 passing jobs on 2026-11-22 to 2026-11-24 the background `supabase start` finished 61 to 96 s after it began (median 71 s, p90 83 s), always on its first attempt. The failed jobs left no log, because the wait step prints the start log only after the exit file exists.
   Root cause, found by reproducing it on this PR (dispatched `ci` run 45367849307, job `e2e (sweeps 1/2)`, whose new wait script printed the log after 420 s): the start itself had failed after 46 s, on all three attempts, with `failed to bind host port 0.0.0.0:54322/tcp: address already in use`. The step shell runs with `-e`, and the background subshell `(bash scripts/ci-supabase-start.sh ...; echo "$?" > exit.tmp; mv ...)` inherits it, so a start that exits 1 ended the subshell before `echo` ran. The exit file never appeared, and the wait step waited its full 8 minutes for a failure that had happened in the first minute. A failed start was therefore always an 8-minute hang, whatever the cause.
   Why the port was taken: Supabase binds 54320 to 54324, inside the runner's source-port range for outgoing connections (32768 to 60999), and the job opens many connections at that moment (image pulls, pnpm install, cache downloads). One of them can hold 54322.
2. The apt stall: run 45331469028, job `deploy`, step "Read-only smoke of the live app" (3 m 55 s, exit 124). That job has no apt cache, so `ci-apt-cache.sh install` went to the mirror for 22 MB of fonts (`fonts-wqy-zenhei`, `fonts-unifont`, `fonts-freefont-ttf`). The mirror served about 100 KB/s. The script's fallback to archive.ubuntu.com changed nothing: Ubuntu 26.04 runners list their mirror in `/etc/apt/apt-mirrors.txt` (the log shows `Get:1 file:/etc/apt/apt-mirrors.txt Mirrorlist`), and the `sed` looked for a `://...archive.ubuntu.com` URL in the sources files, so the second attempt still read `us-east-2.ec2.archive.ubuntu.com` (the same host before and after "switching"). The pattern also could not match a host name with a digit or a hyphen. The deploy job also never wrote the apt timeout and retry settings, which `restore` writes only for the jobs that call it.

## Changes

- [ ] The background start's wrapper runs `set +e` first, so its exit status always reaches the exit file (ci.yml and pr.yml). A failed start now fails the wait step within seconds.
- [ ] `ci-supabase-start.sh` reserves ports 54320 to 54329 (`net.ipv4.ip_local_reserved_ports`) before the first start; every call runs under a hard limit that does not wait for a child stuck in the kernel; 120 s per start (healthy maximum 96 s); at most three attempts inside a 330 s budget; a failed start logs `docker ps -a`, the sockets on the Supabase ports, disk, memory and the supabase and docker processes.
- [ ] `ci-supabase-wait.sh` (new, used by ci.yml and pr.yml): waits for the exit file with its own 420 s limit, below the step's 8 minutes, and on a timeout prints the start log so far, `docker ps -a` and the process list, then fails. No step is retried and no test is touched.
- [ ] `ci-apt-cache.sh`: the mirror fallback rewrites `/etc/apt/apt-mirrors.txt` as well as the sources files (host pattern fixed); the apt timeout and retry settings are written by `install` and `psql` too; one try on the runner's mirror (90 s), then two on archive.ubuntu.com (120 s each, finished downloads are kept between tries).
- [ ] `deploy` restores the Playwright apt cache before the live smoke, like the e2e jobs do.

**Acceptance:** `node --test scripts/ci-cd.test.mjs scripts/ci-supabase-start.test.mjs scripts/ci-apt-cache.test.mjs` passes; the same Playwright projects, specs and shards run; the PR's own run shows the new step durations.
