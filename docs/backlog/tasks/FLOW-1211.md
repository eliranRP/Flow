# FLOW-1211 · Perf: get_breakdown_lines with no key is one computation and a lean row
- **Type:** MEDIUM (perf) · **Status:** claimed (dev lane, 2026-11-16, flow-1210-1211-profit-lines) · **Source:** the perf steward's daily diff review, 2026-11-16 ([report](../../qa/perf/2026-11-16.md)).
- **Files:** a migration (`get_breakdown_lines`, no-key branch only), `packages/shared/src/dashboard.ts`, `app/src/use-company-profit.ts`, pgTAP, app tests.

FLOW-1207's no-key read (`20261114123209_flow_1207_breakdown_lines_all.sql:38-73`) recomputes the whole direction for every page of 200. As Flow QA, page 1 and page 2 cost the same: expense, 2026, is 62.8 ms and 22,452 buffers a page, 5 pages; expense, all time, is 118.4 ms and 43,148 buffers a page, 9 pages. Its rows also carry what this list never reads:
- `group_key` repeats `category_id` under category grouping.
- `kept_out` is always false, and nothing reads it in any mode.
- `currency` equals `p_currency`.
- `shared` has no reader.
- `category_name` is constant per group, and the app already falls back to the breakdown's name.

That is about 150 to 200 of an estimated 450 raw bytes a row.

- [ ] The no-key branch returns the whole direction in one call (no page cap for that branch, or one shared computation), and the app reads it once.
- [ ] The no-key row keeps only what the date and amount list reads (with `group_key` as the filing key). The keyed, kept-out and by-project reads keep every field: flow-mcp names them.
- [ ] pgTAP parity per category against the keyed read, less the dropped fields; app tests.

**Acceptance:** the same lines in the same order; one call per direction; database time and bytes before and after on Flow QA in the PR.
