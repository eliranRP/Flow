# FLOW-1214 · Owner: a forecast skip updates the month's total at once, without refetching the inputs
- **Type:** SMALL (perf, owner decision) · **Status:** claimed (dev task lane, 2026-11-16, flow-1214-skip-patch) · **Source:** the perf steward's daily diff review, 2026-11-16 ([report](../../qa/perf/2026-11-16.md)).
- **Files:** `app/src/forecast-month.ts`, `app/src/company-next-month-query.ts`, tests.

A skip, reset or undo refetches the active `company_next_month_inputs` (`app/src/forecast-month.ts:72-76`; up to 127 KB, 441 ms p50 on the full answer) only to move one key in `skips`. Patching the cached `skips` with `setQueryData` would drop the read, and the month's total would change at once instead of about half a second later. That is visible, so it was the owner's call. The owner chose to update at once (2026-11-16).

- [ ] On a skip, reset or undo, patch `skips` in every cached `company_next_month_inputs` answer for that month with `setQueryData`: active ones, and the slim answer seeded from the full one. Do not refetch them. Keep dropping inactive inputs as FLOW-1201 does.
- [ ] If the write fails, roll back the patch with the existing error toast and undo.
- [ ] Tests: the total changes before the write answers; no inputs read is sent; a failed write restores the total.

**Acceptance:** the month's total follows a skip on the tap; one inputs read fewer per skip, reset or undo.
