# FLOW-1328 · Perf: kept rows keyed by an old day are dropped at launch
- **Type:** SMALL (perf) · **Status:** ready · **Source:** the [2026-11-25 daily report](../../qa/perf/2026-11-25.md), diff review (load scope row 5).
- **Files:** `app/src/kept-reads.ts` (`restoreKeptReads`), `app/src/kept-rules.ts`.

The project forecast (by project, month, day and currency), the loan outlooks (by day) and the company totals (by day and months) are kept on the device with today's date in the key. A row from yesterday is never read again but stays up to 7 days, and `restoreKeptReads` parses and validates every row before the first frame. Five project pages a day leave about 35 dead rows, roughly 400 KB, read on every cold start. The `save` hook (`kept-rules.ts:49`, `kept-reads.ts:196`) has had no user since FLOW-1316 (FLOW-1327 may use it; otherwise remove it).

- [ ] At restore, skip and delete a kept row whose key day is not today, before validating it.
- [ ] Use or remove the `save` hook.

**Acceptance:** no row with an old day survives a launch; a test covers it.
