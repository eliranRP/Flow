# FLOW-1302 · Perf: two small response and kept-size trims
- **Type:** SMALL (perf) · **Status:** ready · **Source:** the 2026-11-24 daily report's diff review (response fields, rows 3 and 6).
- **Files:** a new migration for `recurring_schedule_json`, `app/src/kept-rules.ts` (the month forecast rule), pgTAP and unit tests.

Two small items: `recurring_schedule` sends `ends_on: null` on every row (1,620 of 58,743 bytes per call for Flow QA, measured), while `expected_months` in the same migration sends it only when set and the client type allows it to be missing; and the kept month forecast row also keeps `build`, which is derived from three other kept reads (expected months, unpaid, overrides) plus the edits, and `overrides`, kept again under its own key (tens of KB, estimated).

- [ ] Send `ends_on` only when set in `recurring_schedule` (one migration, a pgTAP test, and check flow-mcp's `get_recurring_schedule` still documents it as optional).
- [ ] Measure the kept month forecast row; if `build` is more than a few KB, keep the inputs and rebuild on restore (as FLOW-1296 does for the Loans schedules).

**Acceptance:** `recurring_schedule` is about 1.6 KB smaller for Flow QA; the kept month forecast row is measured and trimmed if large; nothing on screen changes; the gates pass.
