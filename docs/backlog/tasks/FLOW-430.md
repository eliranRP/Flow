# FLOW-430 · A missing recurring bill suggests a renamed supplier, and the user decides
- **Type:** FEATURE · **Status:** done (#528) · **Depends on:** FLOW-415 · **Source:** owner, 2026-10-10: a water bill showed under "לא הגיעו" because this month's charge came in under a longer supplier name and became a new supplier. The owner's rule: when a name differs, never merge automatically; suggest it and let the user decide.
- [ ] Server: a company table keeps the user's answer for a pair of suppliers (or customers): "same" or "not the same". With "same", `private.recurring_parties` counts the other supplier's lines as the recurring one's, so its bill this month arrives. RLS like the other company tables.
- [ ] Server: `missing_bills()` returns a `suggestion` on a late row: a supplier first seen in the due month (or one month earlier), same direction and currency, no answer yet for the pair, a name sharing its first word, and an amount within 50% of the usual. One suggestion per row, the nearest amount. `answer_recurring_match(...)` saves the answer; MCP gets the same read and write.
- [ ] App, קבועים → לא הגיעו: under the row's hint, "אולי זה: <name> · <amount> · dd/mm" with two buttons, "כן, אותו ספק" and "לא". Yes moves the row out of לא הגיעו; no hides the hint for that pair. Each has an undo toast. Shared component and story; the design lead signs off the row in a PR comment.
