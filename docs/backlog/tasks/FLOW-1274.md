# FLOW-1274 · Perf: profile each main screen's main thread on the phone and cut the largest costs
- **Type:** MEDIUM (perf) · **Status:** ready · **Source:** decision [0271](../../decisions/0271-half-second-by-kept-data-and-one-wave.md), item 4: the perf steward's plan; the perf steward's split of 2026-11-23.
- **Files:** Findings in `docs/qa/perf/`; then the hot files the profile names, each as its own task.

Decision 0271, item 4. On the 2026-11-23 split, a visit's main-thread time is 0.54 to 1.15 s per screen (an upper bound: the whole visit window). Even with kept data and one wave, a screen that spends 0.5 s of CPU drawing on the 4× slower phone cannot show its data within 0.5 s.

- [ ] Record a CPU profile (Chrome tracing, 4× throttle) of an in-app visit to each main screen with kept data and with a cold cache; report the top costs per screen: parse, schema checks, forecast and schedule math, React render and commit, layout.
- [ ] File each large cost as its own task with the measured gain; fix the small ones here.
- [ ] Look first at: the read-schema parse of large answers, `buildMonthForecast`, `companyNextMonthForecast`, `companyRestOfYear`, the loan schedules (`buildLoanSchedule`), `recurringView`, `buildProfitModel`, and lists drawn in full rather than windowed.

**Acceptance:** a per-screen profile in the perf folder, the top costs named with their time, and a task for each large one.
