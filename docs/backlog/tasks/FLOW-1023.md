# FLOW-1023 · Review's first card does not wait on its follow-up reads
- **Type:** SMALL CYCLE (perf) · **Status:** done (#1008, deployed with b1dc1bb) · **Source:** the perf steward's daily report ([2026-11-03](../../qa/perf/2026-11-03.md)), decision [0230](../../decisions/0230-screens-data-in-half-a-second.md).
- **Files:** `app/src/screens/jev-review.ts` and `app/src/screens/jev-review.test.ts` (#1008).

With FLOW-1020 in production (2026-11-03), Review's list read starts about 90 ms after the tap and ends by about 0.7 s on the FLOW-804 phone. Review tapped as soon as Home shows its data still took 0.8 to 4.7 s to settle, p50 2.8 s over 6 runs. In the one slow trace (1,983 ms; the 2.3 to 4.7 s runs were not traced), the time after the list is likely the first card's own reads, started after the list lands:

- `review_anomalies`, `transaction_thread_counts`, `get_line_meta` and `get_line_split` start together at about 0.8 s.
- `company_integrations` starts at the same time. `jev_suggestions` and `tag_suggestions` start once it ends, so they may wait on it (not checked in the code).
- `jev_prefills`, `projects` and `categories` start after those.

Each step likely costs a round trip on 4G (not measured step by step), and each answer may change the card.

- [x] Find which of these reads the card needs before it is useful, and which can fill in after; measure each step's cost first. Traced 2026-11-06 on `45caba4` (3 taps right after Home, FLOW-804 phone): the list ends at about 0.7 s, and the card's counter shows at 0.69 to 0.99 s. After it come three steps: the first batch (`company_integrations`, `review_anomalies`, `transaction_thread_counts`, `list_categories`, `get_line_meta`, `get_line_split`) at about 0.82 s; then `jev_suggestions` and `tag_suggestions`, once `company_integrations` answers (Jev must be known to be on); then `jev_prefills`, `projects` and `categories`, once `tag_suggestions` answers (about 0.56 s later). The screen stops changing at 2.0 to 2.6 s.
- [x] Start the card's reads that do not depend on each other at once: `jev_prefills`, `projects` and `categories` need only the ids, so they now go out with `tag_suggestions` (#1008). The wait on `company_integrations` stays: with Jev off the card reads no suggestion (FLOW-706).
- [x] The card shows its main content (party, amount, date, the approve button) without waiting for the badges: it already did (the counter at 0.6 to 1.0 s); what waited was the screen settling.
- **Acceptance:** unit tests that the card's reads start together; the steward's before and after on the FLOW-804 phone, Review tapped right after Home.
- **Measured (local A/B, 2026-11-06):** main and #1008 built from the same tree, each served locally against production as Flow QA, 4 paired taps on Review right after Home. The screen settles at 1,501 to 1,829 ms with #1008 (median 1,608) against 1,667 to 2,203 ms on main (median 1,943), faster in all 4 pairs. The counter shows at the same time on both.
- **On production (`b1dc1bb`, 2026-11-06), 4 taps:** `jev_prefills`, `projects` and `categories` now start with `tag_suggestions`. The screen settled at 1,928 to 3,266 ms, against 2,022 to 2,580 ms on `45caba4` that morning (3 taps); the network from the cloud agent was slow and uneven that day (round trips up to twice yesterday's, one tap's list read alone took about 1.0 s), so these runs neither show nor rule out the local A/B's gain. Re-measured in the next daily report.
