# FLOW-1271 · Perf: Profit's first view in one wave
- **Type:** MEDIUM (perf) · **Status:** ready · **Source:** decision [0271](../../decisions/0271-half-second-by-kept-data-and-one-wave.md), item 3: the perf steward's plan; the perf steward's split of 2026-11-23.
- **Files:** `app/src/screens/company-profit-screen.tsx`, `app/src/use-company-profit.ts`, `app/src/company-next-month-query.ts`, tests.

Decision 0271, item 3. Profit sends 12 (year), 20 (month) or 26 (by date) requests in 2 waves (2026-11-23 split; 1.9 to 2.1 s). Wave 2 is gated on first paint: the project breakdowns (`get_breakdown` ×2 by project, income and expense, use-company-profit.ts:372-375, `useAfterFirstPaint(figuresIn)`) and the next-month card (`company_next_month_inputs` 127 KB, `loans`, `loan_balances`, `list_categories`, `expected_months`; the gate `useAfterFirstPaint(long ? yearsData != null : model != null)` at company-profit-screen.tsx:164, read by `useCompanyNextMonth`). The comment there (FLOW-1080) records why: the next-month reads wait so they do not share the link with the figures' own reads.

- [ ] Keep the owner's order (FLOW-1080, 2026-11-07, "Keep it"): the next-month card reads after the figures. Changing it needs the owner's go with a measurement.
- [ ] Decide per read whether it is in the first view of each Profit view: the month by project (the default, `/profit`), the month by date (`?by=date`), the month's other orders, and the year and since-the-start periods (`?period=year`, `?period=all`); the split measured the month by project (`/profit`), the month by date (`?by=date`) and the year (`?period=year`); not measured: the month by category (`?by=category`), by amount (`?by=amount`), and since the start (`?period=all`). The project breakdowns that wait for first paint are not drawn in the by-date view; say per mode whether any first-view read still waits, and start it at mount.
- [ ] Wave 1 holds 8 reads on the 4G pipe in the by-date view (`companies`, `get_profit_months`, and `get_dashboard` (month and year to date), `get_breakdown` by category and `get_breakdown_lines` (income and expense each) twice each): measure whether fewer, combined reads would draw the figures sooner, and file what would need a database change as its own task.
- [ ] Tests: the first-view reads of each mode start in one wave; the figures are unchanged.

**Acceptance:** Profit's first view loads in one wave in every mode; data shown falls on the FLOW-1276 sweep; the figures do not change.
