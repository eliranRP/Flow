# FLOW-1086 · Home: skipping a forecast row is swipe-only
- **Type:** SMALL UI · **Status:** done (#1031) · **Depends on:** none
- **Source:** UX rules review 2026-11-07 (run 3, scope 925384f..ae9f7e4a: the v3 build).
- **Files:** app/src/screens/home-activity.tsx, app/src/ui/swipe-row.tsx.

**Finding:** In נותר לשלם / קבועים, "לא החודש" and "החזרה לצפי" exist only as a touch swipe; the under-layer is aria-hidden and the row has no button, so keyboard and screen-reader users cannot do it from Home (the charge page's switch is the only other way).
**Rule:** visual § 9 (keyboard and semantics), motion § 11 (a gesture needs an alternative).

- [x] Give these rows a named control reachable by keyboard (SwipeRow's reveal button with tabIndex 0 when the pointer is not touch, or an accessible action on the row: aria-label naming it plus a key handler). Keep the swipe and the undo toast.
  Done: `SwipeRow keyName` renders the swipe's action as a button after the row ("לא החודש: <name>" / "החזרה לצפי: <name>"), hidden from sight until it has keyboard focus, when the row slides open over it. A screen reader reaches it by name. The swipe, the first-time peek and the undo toast are unchanged. Tests: swipe-row.test.tsx, home-activity.test.tsx (out of the month and back with the button). Story: components-swiperow--keyboard-action.

**Acceptance:** with a keyboard alone, a row in נותר לשלם can be taken out of the month and put back; a test covers it.
