# FLOW-448 · Mark a payment as recurring from the לאישור card
- **Type:** PLAN FIRST · **Status:** design first (waits on the owner's layout pick) · **Depends on:** [FLOW-415](FLOW-415.md) (the "חיוב קבוע" switch and `set_payment_recurring`) · **Related:** [FLOW-447](FLOW-447.md) (the redesigned קבועים tab), [FLOW-439](FLOW-439.md) · **Source:** owner request 2026-10-11 ("i want to be able to mark it if this is a recuring transaction when i see a card, add it to backlog with design before starting")
- **What:** Today a payment is marked recurring only on its own page (the "חיוב קבוע" switch, FLOW-415). Let the owner mark it right on the לאישור card while approving, with the same server call and the same undo toast. Two layouts, drawn on today's card at 390 (project files `mockups/plan-first/flow-448/`):
  - **A, a switch row (recommended):** a third row under פרויקט and קטגוריה, "חיוב קבוע" with the same switch as the payment page. When the app already found it, the switch starts on and the hint says "זוהה לבד". The same control on both screens means nothing new to learn.
  - **B, a text button:** a small accent line under the date, "סימון כחיוב קבוע", that turns into "חיוב קבוע · כל חודש" once tapped. It is lighter, but it is a new control the payment page doesn't use.
- **Acceptance (after the pick):** the card shows the chosen control for a payment with a supplier or customer (none for a line with no party, like the payment page). It reads and writes the same state as the payment page, the change survives approval, and an undo toast follows. Story at 320 and 390, light and dark, plus a unit test. The lane's reviewer checks it against DESIGN-RULES. No build before the owner picks.
