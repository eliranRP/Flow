# FLOW-1043 · Pull to refresh that feels native (the iOS pattern, motion and small details)
- **Type:** SMALL UI · **Status:** in-progress (#981) · **Depends on:** FLOW-1042 (#979) · **Source:** the owner, 2026-11-05: a screen recording of a native iOS banking app's pull to refresh, with "mimic this pull to refresh behaviour and mini interactions so it feels natural". The recording is not in the repo (it shows real data); what it shows is written below in generic words.
- **Files:** `app/src/ui/pull-refresh.tsx` and its test and story, `app/src/ui/css/62-pull-refresh.css`, `docs/design/DESIGN-RULES.md` (ld-07), `docs/design/log/2026-11-05-flow-1043.md`, `docs/changelog.d/2026-11-05-flow-1043.md`.

**What the recording shows (the native iOS pattern)**
- The spinner is the system activity indicator: 12 thin rounded spokes in the secondary text colour, no circle or background behind it, about 20px across.
- While pulling, the spokes appear one by one with the pull (none at the start, all 12 at the threshold), standing still. Past the threshold it starts turning: stepped, one spoke per tick, a full turn about every 0.8 to 1s, with the spokes fading from full to faint around the circle.
- It sits just under the top of the screen (under the safe area, or under a sticky top bar where the screen has one), centred.
- The screen follows the finger closely at first, then with growing resistance (rubber band), with no hard stop.
- On release past the threshold, the screen eases up to a rest just under the spinner (spinner plus a small gap, about 56 to 64px) and holds while it turns. When the data is back, the spinner fades and shrinks a little, and the screen glides back to the top (about 350 to 450ms, a soft ease-out).
- On release before the threshold, the screen glides back the same way and the spokes fade.
- Nothing jumps: the reveal, the turn, the rest and the return are continuous. A pull started during the return picks up from where the screen is.

- [x] The spinner as above, replacing the round raised mark. Built in CSS or SVG with tokens; reduced motion keeps the spokes still and fades them in.
- [x] The pull curve: close to 1:1 for the first part, then the iOS-style rubber band (for example `travel = (1 - 1 / (d * c / h + 1)) * h`, tuned so the threshold of about 64px of travel comes at roughly 110 to 130px of finger move), no hard cap.
- [x] The rest, the hold and the return as above, on the motion tokens (or a new token pair in DESIGN-RULES if none fits), driven from the finger's last position, interruptible.
- [x] A light haptic tick at the threshold where the platform allows it (`navigator.vibrate` where it exists; nothing where it does not), once per pull.
- [x] Keep FLOW-1042: the whole screen moves, the gap takes the screen's top colour (the band on Home), the fixed bars stay put, the 400ms minimum and 15s cap, the reads refetch from Flow's server, no bank sync, the gesture guards, the notch geometry.
- Built (#981): the reference reaches about 170px of travel at about 300px of finger, but it runs close to straight from the start. A curve that slows down and starts 1:1 cannot pass both 64px at 110px of move and 170px at 290, so the build keeps the 1:1 start and the threshold, and reaches about 155px there (`0.5·move + 0.5·21.5·move / (21.5 + move)`); the spinner is 28px, as measured in the reference, and the rest 64px.
- **Acceptance:** unit tests for the curve (monotonic, about 1:1 at the start, threshold at the tuned finger distance, no cap) and the spoke count by progress; stories for idle, pulling at 25%, 50% and 100%, refreshing and returning, at 320 and 393, both themes, with a notch; a Playwright check on iPhone emulation that the screen's position follows a smooth curve over a scripted pull and release (no frame where it jumps more than about 12px); a design log entry.
