# FLOW-1163 · Refresh queue and connections: a skipped run uses up the request, `forced` is dropped, claims are not per slot
- **Type:** BUG · **Status:** done (#1126) · **Depends on:** [FLOW-1160](FLOW-1160.md)
- **Source:** the state machine read of 2026-11-10 ([map](../../tech/state-machines.md), FLOW-1160). Read in the code, not run: check each still happens on `main` first.
- **Files:** `supabase/functions/mercury-sync/index.ts`, `supabase/functions/sumit-sync/index.ts`, `supabase/functions/mercury-connect/index.ts`, a new migration (+pgTAP) for `claim_connector_refreshes`, `note_connector_rejection`, `note_connector_failure`.

- [x] A run that answers `skipped` (the quiet gap, no chosen accounts) leaves its refresh request claimed, so the request is spent without a sync.
- [x] The cron drain passes `forced: false` whatever the request says, so a forced refresh inside the quiet gap is dropped.
- [x] Nothing closes or deletes a claimed request; the rows pile up.
- [ ] `claim_connector_refreshes` and `note_connector_rejection` match on company and provider only: one claim stamps every Mercury slot and one rejection holds them all.
- [x] `note_connector_failure` overwrites `last_error`, so a passing failure after `auth` reads as connected again without a reconnect.
- [ ] Mercury connect clears the cursor and the account choice before the new key is stored; a failure between the two stops the old connection.
- [ ] SUMIT has no resumable cursor: a company past 20 pages fails with `sync_page_cap` on every run.
- [ ] The claim's 10-minute window is a literal in three places; `cron_claim.ts` still says 15.

**Acceptance:** pgTAP for the claim and the two notes per slot; a function test per box; the map's rows updated.

**In #1126:** a request is `queued`, `claimed` or `finished` (deleted), moved by `settle_connector_refresh`: a run that threw or found the connection busy goes back to the queue; one that synced, or skipped for a reason a retry cannot change, finishes it; a request whose run died lapses at the next claim. The claim returns `forced` and both drains pass it on. An `auth` stop survives a later failure or rejection. The claim window is one private function for the claims. **Left:** per-slot claims (the queue is per company and provider by design, and mercury-sync syncs every slot in one run; `note_connector_rejection` has no caller); Mercury connect's clear-then-store (the safe fix is one transaction: a reset flag on `replace_connector_connection`); SUMIT's resumable cursor (a feature); the window literal in `connector_connection_status`, `sumit_status()` and `private.mcp_bank_connection_json`; `stamp_connector_sync` clearing `auth` in a race, and SUMIT's `note_sync_failure` overwriting it.
