# FLOW-1293 · Perf: kept reads that name a day are found on the next day
- **Type:** SMALL (perf) · **Status:** ready · **Source:** decision [0271](../../decisions/0271-half-second-by-kept-data-and-one-wave.md), item 1; FLOW-1292's finding.
- **Files:** `app/src/kept-rules.ts`, `app/src/kept-reads.ts`, the queries whose keys carry a day (`use-cash-to-day.ts`, `project-category-months.ts`, `company-next-month-query.ts`), tests.

FLOW-1292 keeps Home's change pills (`cash_month_to_day`, key has the day), the project page's category months (key has the day) and Profit's next-month inputs (key has today). Those keys change every day, so a kept row only serves a repeat visit on the same day: a user who opens the app once a day gets no kept view for them.

- [ ] Find a way to restore a row under a key the next day's query asks for (keys without today's date, or a kept row put back under the new day's key and read again at once), without showing figures of another day as today's. A day-dependent read must stay correct once fresh data is in.
- [ ] Tests: a row kept yesterday draws today, stale, and is replaced by the fresh read.

**Acceptance:** a user who opens the app once a day sees the kept pills, category marks and next-month card on the first frame.
