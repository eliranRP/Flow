# FLOW-415 · Recurring charges: where they're paid from, a big change on Home, and the user's say on each payment
- **Type:** PLAN FIRST (layout approved) · **Status:** ready · **Depends on:** FLOW-403 · **Source:** owner, 2026-10-10 ("How missing bills works" thread); layout card answered 08:39Z: option A, "Today's screens"
- **Mockups (390px, option A):** project files `mockups/plan-first/recurring/a-1-missing.png`, `a-2-home.png`, `a-3-transaction.png`. The team builds and merges on the design lead's sign-off; no screenshot card to the owner.
- [x] Server: `missing_bills()` returns each row's project and category, the usual day of the month and the last bill's date and amount. A charge that came in this month and differs from its usual amount by 20% or more is returned for Home with both amounts.
- [x] Server: a payment can be marked recurring or not by the user, and that choice wins over the automatic detection in `private.recurring_parties`. A payment can be kept out of the cash view (תזרים) on its own, the way a category can (FLOW-413). MCP gets the same two switches. Done in #493 ([0172](../decisions/0172-recurring-charges.md)): `missing_bills` fields, `recurring_changes`, `payment_recurring`, `set_payment_recurring`; MCP `get_recurring_changes`, `get_line_recurring`, `set_line_recurring`.
- [ ] App, לא הגיעו: each row shows the supplier, then a hint of two lines: "project · category" and "בדרך כלל ב־N לחודש · אחרון dd/mm"; the amount stays "כ־₪…" (a-1).
- [ ] App, Home: the attention card gets one row per big change, "<category> עלה ב־38%" (or ירד), hint "₪now · בדרך כלל ₪usual", with the up/down arrow as on the transaction card; a tap opens that payment. Percentages, never "פי X" (a-2).
- [ ] App, payment page: two switches under נספר ברווח: "נספר בתזרים" and "חיוב קבוע". When the app found it, the hint says "בדרך כלל ב־N לחודש · זוהה לבד"; each change has an undo toast (a-3).
- [ ] Owner additions, 2026-10-10 08:40Z: a recurring charge has a pace the user can change (כל חודש / כל חודשיים / כל רבעון / כל שנה). The server stores it in the user's override, detects it when unset, and `missing_bills()` uses it. In the app, tapping the "חיוב קבוע" row opens a "כל כמה זמן" sheet, and the hint names the pace.
- [ ] Owner additions, 08:41Z: each user can dismiss a late bill row or a change row for themselves, not for the company. The server keeps a per-user dismissal table; a late bill comes back next month and a change stays dismissed for that payment. In the app, a muted 44px ✕ "הסתרה" sits at the row's end, the row can be swiped toward the start, and an undo toast "ההתראה הוסתרה" follows. Home counts only what this user hasn't dismissed.
- [ ] Owner additions, 08:43Z: recurring covers income as well as expenses (late income, change alerts, the switch "הכנסה קבועה" and the pace). The "לא הגיעו" screen becomes "קבועים" (frame b-2), with a "לא הגיעו" section and a "הגיעו החודש" section showing ▲/▼ %. Home's rows open it at their section; when only one charge changed, its row opens that payment, and with two or more it reads "N חיובים קבועים השתנו".
