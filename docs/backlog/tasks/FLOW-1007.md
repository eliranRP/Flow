# FLOW-1007 · Review's first visit waits for no other screen's code, and reads its page once
- **Type:** SMALL CYCLE (perf) · **Status:** done (#911) · **Source:** the perf steward's trace of Review's first visit after FLOW-984 went live (2026-11-01), decision [0230](../../decisions/0230-screens-data-in-half-a-second.md).
- **Files:** `app/src/screen-loaders.ts`, `app/src/screen-loaders.test.ts` (new), `app/src/App.tsx`, `app/src/use-review.ts`, `app/src/use-review.test.tsx`, a changelog fragment.

On the FLOW-804 phone, Review tapped as soon as Home shows its data took 2.1 to 2.4 s. A trace showed two causes, neither the page itself (46 KB, 29 ms in the database):

- The idle preload fetched all ~45 screens at once, about 170 files, as Review was tapped. Review's code waited behind them for about 2 s, and its read only started after its code.
- Each review page was read twice. The supabase-js query builder sends its request each time it is awaited, and `readReviewPage` awaited it twice: once for Jev's scope prefetch, once for the page. The full-list read before FLOW-984 did the same.

- [x] The idle preload fetches the screens 3 at a time, in screenLoaders' order (dev and its e2e still fetch all at once).
- [x] A review page is one request: the builder is wrapped in one promise that both readers share. The test's fake rpc now sends on each await, like supabase-js, so a second await shows as a second read.
- **Acceptance:** unit tests for the preload's limit and order and for one read per page. Built bundles of main and this branch served locally against production, Review tapped as soon as Home shows its data, FLOW-804 phone; the steward's next report re-measures production.
- **Production (2026-11-02 report):** Review tapped as soon as Home shows its data, p50 1.0 s on production. Before, main's build took 2.2 to 2.4 s, measured locally against production in #911. One list read per visit, 3 runs counted.
- **Left for later (FLOW-1020):** Review's own code is a large chunk graph, so its read still starts only once that code is in. Starting the first page's read on the tap, in parallel with the code, would take more off.
