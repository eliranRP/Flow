# FLOW-1255 · Hiding a named late row hides that item, not the next one
- **Type:** SMALL UI · **Status:** ready · **Depends on:** FLOW-1246
- **Source:** UX rules review 2026-11-22 (scope c090b96a..9ee732a3): since #1238 (FLOW-1246) a single late row names its item ("החשבון של A לא הגיע"), but its hide key is still `missing:1` (`app/src/screens/attention-rows.tsx`, the `missing` and `missing-income` rows). If the person hides A's row and later B is the only late bill, B's row is hidden too, under A's dismissal. FLOW-1248's skip filter makes the count move more often. Severity: Low. Rule: feedback-and-states § 10 (a hide applies to what the person hid); hierarchy-and-actions (an alert is not hidden by stale state).
- **Files:** `app/src/screens/attention-rows.tsx`, its test, `app/src/screens/HomeScreen.tsx` and `app/src/screens/project-attention.tsx` only if the key needs the item's id passed down.

- [ ] A named row's key carries its item: `missing:1:<party>:<project|none>` (and `missing-income:1:…`); two or more keep `missing:<count>`. A hide made before this change (the old `missing:1`) still hides, so no hidden row comes back on update; it stops applying once the item changes.
- [ ] Tests: hiding A's named row keeps it hidden; a new single late item B shows; the count row's key is unchanged.

**Acceptance:** each box done.
