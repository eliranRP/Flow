# FLOW-1255 · Hiding a named late row hides that item, not the next one
- **Type:** SMALL UI · **Status:** in-progress (#1250) · **Depends on:** FLOW-1246
- **Source:** UX rules review 2026-11-22 (scope c090b96a..9ee732a3): since #1238 (FLOW-1246) a single late row names its item ("החשבון של A לא הגיע"), but its hide key is still `missing:1` (`app/src/screens/attention-rows.tsx`, the `missing` and `missing-income` rows). If the person hides A's row and later B is the only late bill, B's row is hidden too, under A's dismissal. FLOW-1248's skip filter makes the count move more often. Severity: Low. Rule: feedback-and-states § 4 (cover every state: here, a hide made for one item while another becomes the only late one). No rule file names hides of attention rows directly; the nearest is § 4.
- **Files:** `app/src/screens/attention-rows.tsx`, `app/src/screens/home-attention.test.tsx` (or the test that covers the attention rows), `app/src/screens/HomeScreen.tsx` and `app/src/screens/project-attention.tsx` only if the key needs the item's id passed down.

- [ ] A named row's key carries its item: `missing:1:<party>:<project|none>` (and `missing-income:1:…`); two or more keep `missing:<count>`. The old `missing:1` key carries no item, so it no longer matches a named row: a named row hidden before this change shows once more after the update, and the person hides it again (accepted: an alert showing again is the safe side; a hide that also hides another item is not).
- [ ] Tests: hiding A's named row keeps it hidden; a new single late item B shows; the count row's key is unchanged.

**Acceptance:** each box done.
