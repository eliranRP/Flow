# FLOW-1306 · Perf: the loan schedule in the database, kept current on every loan write
- **Type:** LARGE (perf) · **Status:** claimed (dev lane, 2026-11-24, db/flow-1306-loan-schedule) · **Source:** the FLOW-1275 [plan](../../tech/flow-1275-server-side-math.md), slice 5 (owner approval 2026-11-24).
- **Files:** a migration `<ts>_flow_1306_loan_schedule.sql` (`private.loan_schedule`, `public.loan_schedule_rows`, `public.loan_schedule_meta`, RLS, triggers on `loans` and `loan_rates`, backfill); pgTAP `flow_1306_loan_schedule.test.sql` and the generated vectors file. No app change.

The forecast and the Loans list build every loan's schedule on the phone (`buildLoanSchedule`), twice per call of `paymentsLeft`. The first build, on the loan's own terms and rates, changes only when those do (no write to `loans` or `loan_rates` in production since 2026-11-21), so it is kept in a summary table rebuilt by triggers in the same transaction. The second, the rest of the schedule from the balance in the books, depends on the ledger and on today, so the reads keep building it (FLOW-1307, FLOW-1310), about 1.6 ms a loan in plpgsql. This slice saves the first build only.

- [ ] `private.loan_schedule(p_terms jsonb)`, immutable: every kind, rate changes and recasts, balloon and final adjustment, the exact annuity in `numeric`, interest half to even; refused terms give an error code, as the app's schedule throws. `execute` granted to `authenticated` (it reads no table).
- [ ] The table and its meta row per loan, both with `loan_id references public.loans(id) on delete cascade`, RLS (`readable_company_id`), no write grant to `authenticated`; triggers on `loans` (insert, update of a term column or the status) and `loan_rates` (insert, update, delete; a delete only rebuilds a loan that still exists); deletes are left to the cascade; a backfill.
- [ ] FLOW-1305's loan-schedule vectors equal row for row in pgTAP; a pgTAP case per write path (a rate added, changed, deleted; a term changed; a loan closed; a loan deleted).

**Acceptance:** every vector equal; after any loan or rate write the table equals the function of the new terms in the same transaction; the trigger's time per loan measured on a local database.
