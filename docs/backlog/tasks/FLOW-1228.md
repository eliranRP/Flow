# FLOW-1228 · Drop the unread fields from `get_breakdown_lines`' no-key row once no FLOW-1207 app is in use
- **Type:** SMALL (perf) · **Status:** in-progress (#PR) · **Source:** the perf steward's daily diff review, 2026-11-18 ([report](../../qa/perf/2026-11-18.md)).
- **Files:** one migration patching `public.get_breakdown_lines`, `supabase/migrations.lock`, `packages/shared/src/breakdown-lines.ts`, `app/src/use-company-profit.ts`, pgTAP (`supabase/tests/database/flow_1211_breakdown_lines_lean.test.sql`).

FLOW-1211 (#1204) kept three fields on the no-key row because the FLOW-1207 app's schema requires them. The current app never needs them:
- `currency` is the same on every row.
- `shared` is never read.
- `category_name` is the group's name, which the app already has from `get_breakdown` (it reads `row.category_name ?? input.categoryName`).

That is about 50 to 70 bytes a row raw, about 1,000 rows for a year of expenses: roughly 50 to 70 KB raw a call, about a tenth of that after gzip.

- [x] Leave the three keys out of the no-key row; make them optional in the shared schema and have the app use `input.categoryName`.
- [x] Do it in the same PR as FLOW-1217, or after it, once the FLOW-1207 app is out of use.
- [x] pgTAP: the no-key row is the previous row less these keys.

**Owner's answer, 2026-11-18:** "No need to wait for older versions; there are no users on older versions." Done as one batch with FLOW-1217, FLOW-1224 and FLOW-1228. Migration `20261118091812_flow_1228_breakdown_lines_lean_row.sql`. Production, as Flow QA, read-only, one no-key call (expense, 2026-01-01 to 2026-12-31, USD, `p_limit` null, 856 lines): 337,694 bytes (`octet_length` of the text) before, 275,153 after (the same rows less the three keys, computed in a SELECT): 62,541 bytes fewer, 18.5%, about 73 a row. The app still reads `row.category_name ?? input.categoryName` (a keyed read's row names its category; the no-key row has no name, so the group's name is used).

**Acceptance:** the no-key row has no `currency`, `shared` or `category_name`; the bytes before and after are in the PR; the gates pass.
