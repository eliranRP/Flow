# FLOW-1296 · Perf: keep the Loans list without its payment schedules
- **Type:** SMALL (perf) · **Status:** in-progress (#PR) · **Source:** the 2026-11-24 daily report's diff review (response fields).
- **Files:** `app/src/kept-rules.ts`, `kept-reads.ts`, `app/src/screens/loan-list.tsx` (a type), `app/src/screens/loan-list-kept.test.ts` (new).

The kept "loan list" row held every open loan's full schedule (FLOW-1260), put there for the summary card. For a company of about 20 loans of 30-year terms that is more than 1 MB (about 16% of the 5 MB kept cap for the QA company), stringified and structured-cloned on the phone's main thread at each write and each launch. Nothing needs the schedule kept: the summary's `loanOutlook` builds it when it is missing, and the Loans screen reads `rows`, which carry each loan's next payment and late date.

- [x] `KeptRule.save`: a rule may trim its data when the read is written, before the size is counted.
- [x] The "loan list" rule drops each loan's `schedule`; `LoanListData.loans[].schedule` is optional.
- [x] `rows[]` is kept whole: its late date needs the loan's payments and its project name the project list, neither of which `loans` holds, so it cannot be rebuilt from the kept loans. It is about 5 to 8 KB.
- [x] Tests: the rule trims on save and the size is a fraction of the full row; a restored list draws the same rows and the same summary; the next payment and late date from the restored loans equal the fresh ones; a malformed row is dropped. Mutation check: with `save` removed the size test fails.

**Acceptance:** the kept loan list holds no schedule; a repeat visit draws the Loans list and summary as before; the gates pass.
