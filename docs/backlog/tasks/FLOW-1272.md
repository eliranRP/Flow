- [x] Start what the first card needs together with the list: the connector state, categories and the first card's meta (in one read where it can be), and load the `jev-review` chunk with the screen, not after the list. Per read:
  - `company_integrations` (the connector): starts with the list when Home's cached dashboard names the company (the scope is bound as the card's hook binds it), else as soon as the company's read answers, not after the list's answer and parse.
  - the `jev-review` chunk: requested when the list's read starts (`settleReviewJevScope` runs beside it), not after the list.
  - `list_categories`: starts with the list, on the card queue only (`/review`); the list view (`/review/all`) shows none.
  - `tag_suggestions`, `jev_prefills`, `projects`, `categories`, `jev_suggestions`: need the cards' ids, so they go out when the list answers; the ids are read from the raw page, no longer after the read schemas load, and the queue read follows the connector's answer, which is now in before it.
  - `get_line_meta` (already one read for the cards ahead), `review_anomalies` and `transaction_thread_counts`: need the ids, so they start when the card mounts after the list. Starting them from the list's answer measured no gain on the phone profile (the main thread is busy drawing) and cost 1.3 KB of the bundle, so they stay as they are; with kept rows (FLOW-1267) they start at mount.
- [x] Share `list_jev_bookings` between Home's count and Review (one key). `["jev-bookings", preview]` holds the server's rows; Home's count is a `select`, Review's queue parses with `select`. One query has one retry setting (a shared query takes the options of the observer that rendered last), so the read has none, set on the shared options: Review waits for it before its first draw, and Home counts a failed read as zero. `kept-rules.ts` has no rule for either key, so it is unchanged.
