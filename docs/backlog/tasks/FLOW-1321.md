# FLOW-1321 · CI: main red on the Edge Function source scan, and the pr check never runs it
- **Type:** BUG (CI) · **Status:** claimed (dev lane 1, 2026-11-24, fix/flow-mcp-vectors-scan) · **Source:** `ci` run 45413251361 on main, job `check (core)`, step "Stamp the commit and check the hosted bundle".
- **Files:** `scripts/check-prod-bundle.mjs`, `scripts/check-prod-bundle.test.mjs`, `scripts/local-ci-parts.sh`, `scripts/ci-cd.test.mjs`, `supabase/functions/flow-mcp/tools_forecast_test.ts`, `supabase/functions/flow-mcp/tools_forecast_vectors.ts` (deleted), `packages/shared/src/vectors.test.ts`.

## Evidence

`pnpm check:bundle` failed on main with `tools_forecast_test.ts contains fixtures/` and `tools_forecast_vectors.ts contains fixtures/`. FLOW-1312 (#1295) added a vectors module in the function folder that imports the shared synthetic vectors, and the source scan refuses the `fixtures/` marker in any Edge Function source. The `pr` workflow never runs that scan (only `ci` on main and deploy do), so the PR was green.

## Changes

- [ ] The vector imports move into `tools_forecast_test.ts`; `tools_forecast_vectors.ts` is deleted. The scan skips `*_test.ts` files only, which `supabase functions deploy` cannot reach.
- [ ] A new check fails when a file that is not a `*_test.ts` imports one.
- [ ] `pr (static)` runs the source scan (`node scripts/check-prod-bundle.mjs --sources-only`, no build).
- [ ] `vectors.test.ts` parses the imports in the test file.

**Acceptance:** `pnpm check:bundle` passes on a built dist; the scan still flags every marker in a shipping file.
