# FLOW-1115 · A cold start on Home sends its figures' reads before the first render
- **Type:** SMALL CYCLE (perf) · **Status:** done (#1066, deployed with 9cbf714) · **Source:** the perf steward's daily pass, 2026-11-09; decision [0230](../../decisions/0230-screens-data-in-half-a-second.md).
- **Files:** `app/src/home-early-reads.ts` (new) and its test, `app/src/main.tsx`, `app/src/use-books.ts` (`dashboardQueryOptions`), `app/src/use-cash.ts` (`cashMonthsQueryOptions`).

Cold Home on production (FLOW-804 phone, 2026-11-09): the page arrives at 150 to 300 ms and Home's code at 550 to 980 ms. The first Supabase read only leaves about half a second later (1,043 to 1,563 ms), once React has drawn its first frame and Home has mounted. The reads then take about 0.8 s, and Home's figures wait on two of them: `cash_months` (Home's four months) and `get_dashboard` (the P&L).

- [x] `main.tsx` starts those two reads right after it creates the query client, before the first render, through the same query options Home's hooks use (same keys), so Home picks them up instead of sending its own. Only on Home (`/`), not in a preview (`?preview=`), and only with a session.
- **Acceptance:** a unit test that Home's own queries send no second read; the steward's local A/B of cold Home on the FLOW-804 phone; the same reads count.
- **Measured (local A/B, 2026-11-09):** main `1bd3baa` and this change built from the same tree, served locally against production as Flow QA, cold Home on the FLOW-804 phone, 3 alternating rounds of 5 loads. Home's figures at a median 1,362, 1,448 and 1,414 ms with the change, against 1,954, 1,796 and 1,825 ms on main: about 0.4 s sooner in every round. 24 reads per load on both.
