# FLOW-1195 · Perf: Company profit's year view reads forecast skips once, not once per month
- **Type:** SMALL (perf) · **Status:** in-progress · **Source:** the perf steward's daily diff review, 2026-11-14 ([report](../../qa/perf/2026-11-14.md), finding 10).
- **Files:** a new migration in `supabase/migrations/`, `app/src/company-next-month-query.ts` and its test, `packages/shared/src/database.types.ts`, pgTAP.

In full mode (the year and since-start views), `company-next-month-query.ts:94-95, 165-167` still sends one `forecast_overrides_for` per month left in the year: 1 in November, up to 11 in January. The month view already sends one.

- [x] Return the skips by month inside `company_next_month_inputs`'s `p_rest` answer, or add a range read.
- [x] The app sends one read for the year view.

**Acceptance:** the year view sends one skips read in January as in November. The answers are equal, shown by the app's tests and pgTAP.

**Built:** the same migration. `company_next_month_inputs(p_rest true)` returns `skips`, the moved-out item keys by month (next month to the forecast's last, a month with none has no key); `forecast_overrides_for` stays for the month pages. The app's year and since-start views read `skips` from the answer and send no `forecast_overrides_for`; next month's own card still reads next month's once. pgTAP: `flow_1195_year_skips.test.sql`. App: `company-next-month-year-skips.test.tsx`.
