# FLOW-1273 · Perf: code a screen needs loads with the screen, not after its data
- **Type:** SMALL (perf) · **Status:** ready · **Source:** decision [0271](../../decisions/0271-half-second-by-kept-data-and-one-wave.md) (owner, 2026-11-23); the perf steward's split of 2026-11-23.
- **Files:** `app/src/month-forecast-query.ts`, `app/src/load-read-schemas.ts`, `app/src/screen-loaders.ts`, tests.

Decision 0271, item 3. Some code chunks load only after their data arrives, adding a chunk fetch and parse to the wait: `month-forecast-build` (`import()` after the four forecast reads return, month-forecast-query.ts:48) and the read schemas (`loadReadSchemas`, load-read-schemas.ts:9, awaited after almost every response). Review's `jev-review` chunk is FLOW-1272.

- [ ] Start these imports when the screen or the read starts (in parallel with the request), not after the answer.
- [ ] Check the bundle budget (`pnpm check:bundle`); keep them lazy, only earlier.
- [ ] Tests: the import starts before the response is parsed.

**Acceptance:** no first-view chunk waits for its data; the bundle stays within budget.
