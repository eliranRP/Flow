# FLOW-1220 · The project ⋯ menu does not move under a finger when the delete check lands
- **Type:** PLAN FIRST · **Status:** plan-first · **Depends on:** none
- **Source:** UX rules review 2026-11-16 (scope 1321ffca..5cf22eb7): #1186 (made more frequent by #1205): when the menu opens before its read lands, a skeleton row holds the delete slot at the bottom of a bottom-anchored sheet; on landing it becomes the delete row, or nothing (the usual case: a project with lines cannot be deleted). Removing it moves every row above by about one row (`--row-height` + the sheet gap), so a tap aimed at "סיום הפרויקט" can land on the row next to it. Severity: Medium. Rule: feedback-and-states (reserve space while loading; no layout shift); tables-and-responsive § 21 (touch targets).
- **Files:** `app/src/screens/project-menu.tsx`, `app/src/ui/css/32-project-page.css`.

- [ ] The owner picks: (a) when the check says the project cannot be deleted, the slot keeps its height as a quiet, non-tappable line ("אי אפשר למחוק: יש בו תנועות"); (b) the delete slot moves to the top of the sheet, so a change there never moves the rows under the finger; or (c) another way. The owner's 2026-11-15 placeholder decision (FLOW-1204) stays.

**Acceptance:** each box done, with a story or test for each fixed state at 320 and 393.
