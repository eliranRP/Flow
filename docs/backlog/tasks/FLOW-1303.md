# FLOW-1303 · The splash ends when Home's figures are drawn
- **Type:** SMALL UI · **Status:** in review · **Source:** the owner, 2026-11-24, "End when data is ready" (the answer to the perf steward's question: on a real phone the splash covers about 2.9s of every cold start, which hides kept data that is ready at about 0.3s).
- **Files:** `app/src/ui/splash.tsx`, `app/src/ui/splash-ready.ts`, `app/src/ui/splash.stories.tsx`, `app/src/ui/splash.test.tsx`, `app/src/ui/splash-ready.test.ts`, `app/src/ui/splash-tokens.test.ts`, `docs/design/DESIGN-RULES.md` (§2.7), `docs/tech/state-machines.md`, `docs/qa/CONTROLS.md`, `docs/design/log/2026-11-24-flow-1303.md`, `docs/changelog.d/2026-11-24-flow-1303.md`.

FLOW-1277's splash runs a fixed animation: liquid 2,400ms, wordmark from 2,300ms, a 160ms fade, about 2.9s, plus a 3s failsafe on the cover. It now ends when Home's first figures are drawn.

- [x] The signal, read from the DOM (nothing added to Home's entry): Home's figures marker `.ui-band-body .ui-num` is there with no skeleton (`.ui-skeleton-bar, .ui-skel-row, .ui-skel-leaving, [aria-busy=true]`), or the app shows a route other than Home, or an error state (`.ui-band-failed, .ui-page-failed`) is up.
- [x] At least 800ms on screen, then the 160ms fade. When the data is ready before the animation's end, the rest of the fill is played faster (the playback rate, so the motion stays continuous) and arrives in 400ms, or by the 800ms mark; it is never cut off mid-wave.
- [x] The 3s failsafe is the most: with no data the splash is gone at 3s (the fade starts at 2.84s). A signed-out start (the login screen) and an error screen end it at the minimum.
- [x] Kept: a tap or a key skips it, reduced motion (the finished icon for 400ms, no wait for data), `aria-hidden`, never under `navigator.webdriver`.
- [x] The watch is one `MutationObserver` on the body (childList, subtree, `aria-busy`), with no timer or polling; the browser batches its callbacks, and it is disconnected when the splash ends (ready, tap, key, failsafe or unmount). Chosen over an event from Home because it adds no bytes to the Home entry (under 1 KB of room) and no code on Home's first render.
- [x] Tests with fake timers (data at 300ms, at 1,500ms, never; signed-out; error; tap; reduced motion; the observer disconnected) and a mutation check of the "ends when data ready" logic; stories for "data ready early" and "data late (failsafe)"; DESIGN-RULES §2.7, the state machine row, CONTROLS and a design log entry.

**Acceptance:** each box done; the Home entry stays under 248 KB and the total under 745 KB.
