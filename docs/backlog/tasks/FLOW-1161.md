- **Files:** `app/src/setup/steps.tsx`, `app/src/setup/skip-all.ts`, `app/src/setup/model.ts`, `app/src/setup/route-screens.tsx`, `app/src/screens/settings-screen.tsx`, their tests.

- [x] Step 1: when `create_company` succeeds and a first setting is refused, the retry takes the existing-company path: the run's start (`run_started_at`, `flow_at`) is never stamped and the starter categories are not retried. With `?new=1` the retry creates a second company.

- [x] Steps 3 and 5: דילוג and back stay live while the step saves.
- [x] After skip-all the Settings entry still shows, and its link lands on Home (`settingsEntryVisible` ignores `skipped_all_at`).
- [x] Settings counts the steps left as `5 - done` while the setup has 7 (`SETUP_TOTAL`).
- [x] Step 2's "no bank" button records neither done nor skipped.

**Acceptance:** each box with a test; the wizard's run and step states are tables per decision 0266, and the map's row moves to "Explicit machines".

**In #1125:** fixed the refused setting after the company exists (the retry resumes the follow-up, with no second company), the silent skip-all, the controls live during a save (steps 1, 3 and 5), and the steps-left count. **Left:** the Settings entry after skip-all stays by design (the skip sheet says so), but its link lands on Home: a product call. **Decided by the owner, 2026-11-10:** after skip-all the Settings entry's link opens the first setup step not yet done (approved option "Open first open step"). Step 2's "no bank" counts the step as skipped (approved option "Count as skipped").

**In #1128:** the Settings entry opens the first step not done, also after skip-all (`settingsEntryTarget`; `/setup` itself still lands on Home after skip-all); step 2's "no bank" records the step as skipped. **Left:** the wizard's run and step states are not a table yet.

**In #1159:** the run and the step are tables in `setup/model.ts` (decision 0266). `setupRun` (`fresh`, `started`, `resumed`, `skippedAll`, `finished`) is read from the run's stamps; `withPatch` moves a patch's run stamps through it, so a second start, a resume after skip all or a second finish keeps the stored stamp, and `skipAllPatch` changes nothing the second time. `setupStep` (`open`, `skipped`, `done`) reads each step as one state, done winning over a stored skip; a skip is written only on an open step, and approving the sample again changes nothing. `runMayResume`, `indexTarget` and the Settings entry read the run state; what #1125 and #1128 fixed stays (their tests pass unchanged). The map's row moved to "Explicit machines". **Left:** nothing.
