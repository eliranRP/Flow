# FLOW-1031 · Home keeps the forecast row's place while it loads
- **Type:** SMALL UI · **Status:** done (#965) · **Source:** UX rules review 2026-11-04 (`docs/runbooks/ux-rules-review.md`, rules in `.claude/skills/ux-ui-design-review-rules/`). Severity: Medium. From FLOW-1019 (#956; the owner chose to read the forecast after Home appears).
- **Files:** `app/src/screens/HomeScreen.tsx`, `app/src/ui/css/07-band-home.css`.

- [x] On a cold load the forecast row (63px) and the next-month block arrive after Home paints and push the attention rows down, under a thumb already aiming. Reserve the row's height while the read is pending on the current month, or fade it in without moving what is below. Rule: motion § 1; feedback-and-states § 2 (no layout shift).

**Acceptance:** a story or test shows the attention rows at the same position before and after the forecast arrives.

**Done (claude/flow-1030-changes-home-ux):** the forecast is still read after Home paints (FLOW-1019). Until the read answers on the current month, `CashHome` draws the row's own box (`ForecastRow` with `minor` null: the title and line, a band bar for the figure, not a link), so the figure lands in place; the row leaves only when the read fails or nothing is still expected. The next-month block sits below the attention box and the split card, so its arrival moves only the reports card below it; it is left as it is. Story: Screens/Routes, "Home, forecast row kept while it loads", whose play checks the attention box's offset before and after the figure arrives; test in `home-cash.test.tsx`.
