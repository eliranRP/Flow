# FLOW-1019 · Home's cold load reads each list once, and next month's numbers without a second wave
- **Type:** PLAN FIRST (perf) · **Status:** plan-first · **Source:** the perf steward's daily report ([2026-11-02](../../qa/perf/2026-11-02.md)), decision [0230](../../decisions/0230-screens-data-in-half-a-second.md).
- **Files:** to be named in the plan (Home's forecast and next-month cards: `app/src/month-forecast-query.ts`, `app/src/company-next-month-query.ts`, `app/src/use-books.ts`, the Home screen; possibly a lighter next-month read).

Cold Home on the deployed app (FLOW-804 phone) took 7.5 to 8.5 s on 2026-11-02, against 3.0 to 5.2 s on 2026-10-31 and 11-01. The build-only cold Home is not slower (`load-report` 1,192 ms, against 1,344), so the time is likely in Home's reads. A trace of one cold load:

- **About 30 reads.** 16 start together at 1.25 s, once the code has run.
- **Two reads go out twice under different cache keys:** `list_unpaid` (Home's unpaid row, and the month-forecast query) and `expected_months` (the forecast row, and the forecast query). `loans` is also read twice.
- **A second wave starts at about 3.6 s, after the first wave answers.** It holds `company_next_month_inputs` (105 KB, 229 ms in the database, the slowest of the reads the steward times), `cash_months`, `expected_months`, `loans`, `list_categories` and `weekly_summary`. The last read ends at about 5.4 s, and the CPU-throttled render finishes about 2 s later.

Between the 2026-11-01 build (176ba4d) and 2026-11-02's (da79343), the likely candidates are not yet measured one at a time:

- #917 (FLOW-1008): the month-forecast query that reads the two lists again.
- #932 and #933: the recurring tip and the icon count, which add reads to Home.
- #909: the enforced CSP.
- #911 and #934: the idle preload.

The first step is to measure each.

- [ ] Plan approved by the owner: which reads Home needs before it paints, and which can wait or merge.
  - The month-forecast query can take `list_unpaid` and `expected_months` from Home's own queries (`ensureQueryData` on the same keys), not read them again.
  - The next-month card can read only its totals, not the per-project category months `company_next_month_inputs` returns for Company profit.
  - The second wave could start with the first, or after first paint.
- [ ] Cold Home on the deployed app is back under its 2026-10-31 range, measured by the steward.
- **Acceptance:** unit tests that each list is read once on Home; the steward's before and after on the FLOW-804 phone.
