# FLOW-1142 · Utility refunds: each bill and payment opens its transaction page
- **Type:** SMALL UI (owner's ask) · **Status:** in-progress (dev lane 1, 2026-11-09, claude/zen-keller-w90qi6) · **Depends on:** [FLOW-1141](FLOW-1141.md)
- **Source:** the owner, 2026-11-09, from the phone on the live החזרי חשבונות screen: "I want to be able to open each transaction page so I can dig in and verify it."
- **Files:** a new migration (+pgTAP) that redefines `public.list_utility_refunds`; `app/src/utility-refund-schema.ts`, the sample and stories; `app/src/screens/utility-refunds-parts.tsx`, `utility-refund-sheet.tsx`, `utility-refunds-screen.test.tsx`; `app/src/utility-refund-view.ts`; `app/src/ui/css/65-utility-refunds.css: .ui-urf-leg-link, .ui-urf-leg-chevron`; the design log; a changelog fragment.

- [x] On a suggestion card, each leg opens its transaction page (`/transactions/:id`): the bill and the payment. The whole leg is the tap target, with a chevron at its end.
- [x] A payment that refunds several bills lists each bill as its own leg (supplier, category · date, amount), and each opens its own transaction. It used to be one joined leg ("A + B").
- [x] The bill's sheet gains פתיחת התנועה, which opens the bill's transaction.
- [x] A viewer's bill row opens the bill's transaction, since a viewer has no sheet.
- [x] The payment leg shows the payment's project, and its split parts when it is split (category, project, amount), so the owner can see where a rent-plus-bill payment went (the owner, 2026-11-09). `list_utility_refunds` adds `project_name` and `parts` to each payment.
- **Acceptance:** tests for every link and for the per-bill legs; the utility refund stories pass; lint, typecheck and the unused-code and unused-CSS checks pass.
