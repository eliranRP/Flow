# FLOW-816 · The project-open speed check scales to the container in local gates
- **Type:** SMALL CYCLE · **Status:** claimed (dev lane 4, 2026-10-10, claude/flow-601-team-invites-dbh8bx) · **Depends on:** — · **Source:** lane manager, 2026-10-10: `perf/project-open.spec.ts` failed on slow containers, not slow code (768/778 ms in one container, main itself 744-764 ms in another, 723-809 ms in a third, while CI opened the same project in about 150 ms).
- [ ] CI (`GITHUB_ACTIONS`) keeps the bare 700 ms limit. A local gate first times a fixed bench (sorting and serializing rows, then drawing and laying out a list) at the same CPU ×4, in the same run. The limit becomes 700 ms × the bench's slow-down against CI's median, at least 1 and at most 1.5. The spec prints the bench samples and median, the factor and the limit in effect beside the open times. There's no skip and no retry. `app/perf/container-speed.ts` holds the bench. CI's bench median is an estimate (90 ms) until main's run prints its own.
