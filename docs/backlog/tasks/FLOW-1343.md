# FLOW-1343 · Perf: Home stops loading setup for a card that draws nothing
- **Type:** SMALL (perf) · **Status:** in-progress (#1314) (the owner's go, 2026-11-27: "Remove it") · **Source:** the diff review of #1311 (FLOW-1342) in the 2026-11-27 daily report.
- **Files:** `app/src/setup/home.tsx` (deleted), `app/src/setup/entry.tsx`, `app/src/setup/on-demand.tsx`, `app/src/setup/gate.ts`, `app/src/setup/server-store.ts`, `app/src/setup/model.ts`, `app/src/setup/storage.ts`, `app/src/setup/route.tsx`, `app/src/screens/HomeScreen.tsx`, and their tests.

Home's setup slot drew nothing: its completed-toast rule (`shouldShowCompletedToast`) returned `false` ("gated off until #622", which merged). Yet for an owner with a started, unfinished run, every cold Home loaded the setup chunk and read `setup_states` plus five step reads, and the gate read the row again for viewers and editors.

- [x] Remove the slot (`SetupHomeSlot`, `home.tsx`, `flagsOpenForSlot`, both HomeScreen mounts), the toast rule and its `completed_toast_at` stamp, and the Home card's legacy stamps nothing else reads (`confirmed_lists_at`, `ios_steps_seen_at`, `card_dismissed_at`). Saved rows that still hold them parse; the keys drop on the next save. No migration.
- [x] The gate's row is reused by the setup store: one cold Home makes at most one `setup_states` read.
- [x] A locally stamped `finished_at`, `skipped_all_at` or `run_resumed_at` is final: no server read. A phone with no local copy still reads once.

**Acceptance:** a cold Home for an owner already resumed loads no setup chunk and reads no `setup_states` row or step data; a finished owner with a local copy reads no row; a new phone with an open run still resumes, with one row read.
