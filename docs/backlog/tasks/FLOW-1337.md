# FLOW-1337 · Loans list offline on a new day shows the loans, not "אין הלוואות"
- **Type:** SMALL UI · **Status:** ready · **Depends on:** FLOW-1316
- **Source:** UX rules review 2026-11-25 (scope 9ee732a3..e6b901f6): since #1287 (FLOW-1316) the Loans list's rows need two reads, the list (`balances`) and `loan_outlooks`, and the outlooks read is keyed by today (`["loans", companyId, "outlooks", today]`, `app/src/screens/loan-reads.ts`). Both are kept on the device, but yesterday's outlooks sit under yesterday's key. Opened offline on a new day, the outlooks read is paused with no data (not loading, not failed), so `liveRows` is null and `app/src/screens/loans-host.tsx` draws `rows = []`: the empty state "אין הלוואות" with its add button, while the loans are on the device. Severity: Medium (misleads: the loans look gone). Rule: feedback-and-states § 4 (cover every state: offline is not empty); onboarding-and-empty-states (an empty state never shows when there is data).
- **Files:** `app/src/screens/loans-host.tsx`, `app/src/screens/loan-reads.ts` (if the fix keeps the last outlooks), a story `list-offline-new-day` beside the Loans stories, a test.

- [ ] With the list on the device and no outlooks for today (paused offline, or still pending), the rows draw from the list with no next payment and no late mark (or with the last kept outlooks, said as of their day), with the offline line; never the empty state. A failed outlooks read keeps today's behaviour (FLOW-1316: it fails the list).
- [ ] Story and test: kept list, outlooks paused offline: rows show, no "אין הלוואות".
