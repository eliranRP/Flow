# FLOW-1167 · Shared UI parts: holds and flags that can stay set (toast, sheet, list hold, swipes, disconnect, reload)
- **Type:** BUG · **Status:** ready (most of it in #1125 and #1159; left: a close check that never settles, and the toast as a table) · **Depends on:** [FLOW-1160](FLOW-1160.md)
- **Source:** the state machine read of 2026-11-10 ([map](../../tech/state-machines.md), FLOW-1160). Read in the code, not run: check each still happens on `main` first. UI lanes: no look changes.
- **Files:** `app/src/ui/toast.tsx`, `ui/sheet.tsx`, `ui/back.tsx`, `ui/change-sheet.tsx`, `ui/period-swipe.tsx`, `ui/swipe-row.tsx`, `app/src/list-hold.tsx`, `connection-undo.ts`, `connection.ts`, `sw-reload.ts`, `push.ts`, `txn-list-more.ts`, their tests.

- [x] Toast: a mouse press released outside the toast leaves `press` set and the dismiss timer paused; `hold` carries over to a replacement toast; the swipe path clears `press` without resuming.
- [ ] Sheet: `closing` is cleared only when `open` turns true or `onOpenChange` returns `false`, so a parent that ignores the close leaves every later close a no-op; a `onBeforeClose` that never settles blocks all closes.
- [x] Change sheet: at `new`, the browser's Back lands on the summary and the sheet's back on the picker.
- [x] List hold: a pointer that never reports up keeps `press` set (no reset on blur or when the page is hidden).
- [x] `PeriodSwipe` drops a second finger without settling; `SwipeRow` stays open when `reveal` goes away, and its action stays live when `disabled` turns on.
- [x] Disconnect with undo: a rejected `onSent` leaves the entry for good; starting a disconnect on a key that is waiting drops the old entry's callbacks.
- [x] Online state: a reachability check started for one offline event can set online after a later one.
- [x] New version reload: the loop guard clears `pending` first, so the reload is dropped.
- [x] Push subscribe: a throw in the controller step reports `worker-timeout`, and the outer limit always reports the `subscribe` step.
- [x] `useTxnListMore` replaces the entry while an earlier load still writes the old one.

**Acceptance:** each box with a test; the toast, the sheet and the disconnect entry are tables per decision 0266.

**In #1125:** the disconnect entry is a table (`disconnectFlow`) and ends however its redraw goes; a toast's press released outside resumes its timer and a new toast starts with no hold; the list hold lets go on blur and when the page is hidden; `PeriodSwipe` settles on a second finger; `SwipeRow` closes when its action goes and ignores it while disabled; an online check answers only for the offline event that started it; a held-back reload is kept; a list's load in flight survives its entry being registered again. **Left:** the sheet's `closing` flag (the fix is in the six loan sheets, see FLOW-1164); the change sheet's two backs at `new` (no doc or test says which is right: a design call); push subscribe's reported step (needs a new result and its copy). The toast and the sheet are not tables yet.

**Decided by the owner, 2026-11-10:** at the change sheet's new-item view, the browser's Back and the sheet's back both go one step back, to the picker (approved option "Both to the picker").

**In #1128:** the change sheet's `new` view has its own browser entry, so the browser's Back and the sheet's back both land on the picker, in both modes; a create or a close pops it first. In contained mode a second Back closes the sheet, as Back on a contained picker already did.

**In #1159:** the sheet's close is a table (`sheetClose`: `closed`, `open`, `queued`, `deciding`, `closing`), keeping the order `onBeforeClose`, `onCloseKind`, `onOpenChange(false)`. After an allowed close the sheet stays `closing` while the parent still draws it open: a close asked within `SHEET_CLOSE_SETTLE_MS` (1000 ms, longer than a history pop) is the same close, so a parent that closes a moment later closes once and keeps the Escape ring; a close asked later is heard and asks `onBeforeClose` again, so a parent that ignored the close no longer leaves later closes doing nothing. A close asked in the commit that opens the sheet is heard; a decision that lands after the parent closed or unmounted the sheet sends nothing. Push subscribe's steps are a table (`subscribeFlow`): a timeout, a throw and the outer limit report the step the run was in, and a wait for the worker's control that throws reads as not controlled instead of a worker timeout; a throw at the permission step is a failed subscribe, not a denial; no copy changed. **Left:** an `onBeforeClose` that never settles still holds later closes until the parent closes or reopens the sheet: asking again could save twice, and a timer could close over an unsaved edit, so no safe rule was found (a test records it). The toast is not a table yet (its phases are set from six places; not a small change).
